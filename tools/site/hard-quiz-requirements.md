# Требования к сложному экзамену блока (New · сложный)

Банк `js/api-<блок>-hard-quiz.js`, формат тот же (`window.QUIZ_BANK`, свой `id`, например `api-rag-hard`).
Пишет модель Fable: если сессия не на Fable, на каждый блок запускать субагента `Agent` с `model: "fable"`,
передав ему путь к дампу уроков блока, путь к нашим урокам, пример вопроса и этот файл целиком.

Источник вопросов — только содержание уроков блока (дамп Skilljar и наши уроки с «Пояснениями») плюс
актуальная документация platform.claude.com для фактов. На сертификационном экзамене вопросы сценарные
и заметно сложнее базовых банков — нужен этот уровень.

Чего не надо: математики, вычислений, чтения или написания Python-кода, вопросов на имена функций SDK.
Имена параметров и полей API (`stop_reason`, `tool_choice`, `cache_control`, `input_type` и т. п.) можно,
если они ключевые для смысла урока.

Что надо:

1. Сценарий. Команда или продукт, конкретная ситуация, симптомы. Вопрос «что лучше всего сделать»,
   «что вероятнее всего причина», «что сделать первым», «какой подход НЕ решает проблему».
2. Решающая деталь в конце условия. Ограничение (бюджет, задержка, приватность, объём данных, тип
   документов, кто вызывает инструмент), без которого выбор неоднозначен. Без полного прочтения вопрос
   не решается.
3. Все варианты правдоподобны. Неправильные варианты — это: верное утверждение, которое не отвечает на
   этот вопрос; правильный приём, но для другого этапа (чинят генерацию, когда сломан поиск); частично
   верное решение, не учитывающее ограничение из условия; устаревшая практика или распространённое
   заблуждение. Никаких абсурдных или шутливых вариантов.
4. Форма не подсказывает ответ: варианты одной длины (±20%) и одной грамматической формы; правильный не
   самый длинный и не самый подробный; без «always/never» как маркеров неправильного; правильные буквы
   распределены примерно поровну по a/b/c/d, «d» правильный не реже других.
5. Разные типы вопросов: ~20% multi-select (с «Choose two»), сравнение двух подходов, диагностика по
   симптомам (`stop_reason`, что вернул поиск, поведение агента), trade-off-вопросы.
6. Каждый вопрос на английском. Поле `why` объясняет, почему правильный вариант правильный и почему каждый
   неправильный не подходит, со ссылкой на урок.
7. Объём: как у базового банка блока (16–18 вопросов), у итогового экзамена 36, с тем же делением по
   темам (`domain`).

Контроль качества перед коммитом:

- `python3 tools/site/quiz_check.py js/<банк>.js` — буквы поровну, «правильный самый длинный» < 30%,
  длины вариантов в ±20%, без always/never, структура без ошибок. Показать владельцу цифры нового банка
  рядом с цифрами старого банка блока.
- Проверка «вслепую»: субагент без доступа к урокам решает банк, видя только вопросы (без `correct`
  и `why`). Если он отвечает правильно больше чем на ~50%, вопросы, угаданные по форме или здравому
  смыслу, переписать.
- Факты сверены с дампом уроков и документацией, а не написаны по памяти.
