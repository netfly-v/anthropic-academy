Смотреть урок на Skilljar Project setup · 3:09

Чтобы лучше разобраться в некоторых аспектах MCP, мы начнём писать собственный чат-бот с интерфейсом командной строки (CLI). Так станет понятнее, как клиенты и серверы на самом деле работают вместе. В этом видео мы немного подготовим проект и разберём, что именно будем делать.

На экране — подробное описание того, что мы построим. Разбирать его будем постепенно, а пока достаточно общего представления.

Что строим

Как уже говорилось, это будет чат-бот для командной строки. Пользователи смогут работать с набором документов. Документы ненастоящие — они просто хранятся в памяти.

Мы напишем небольшой MCP-клиент, который подключается к нашему собственному MCP-серверу. Пока на сервере будут два инструмента:

  • один читает содержимое документа;
  • другой обновляет содержимое документа.

Сами документы показаны на схеме справа. Все они ненастоящие, поэтому хранятся только в памяти. Вот и всё.

Важное замечание

Прежде чем идти дальше, сделаем очень важное замечание обо всём этом процессе — его стоит как следует понять. В обычном проекте, как правило, реализуют что-то одно: либо клиент, либо MCP-сервер.

  • В реальном проекте мы могли бы написать только MCP-сервер — чтобы опубликовать его для всех и дать разработчикам доступ к какому-то сервису, который мы создали.
  • Или, наоборот, сделать только MCP-клиент. Тогда задача — подключаться к внешним MCP-серверам, которые уже написали другие инженеры.

В этом проекте мы делаем и клиент, и сервер. Оба — в одном проекте, просто чтобы вы лучше поняли, как они работают вместе.

Подготовка проекта

С этой оговоркой разобрались — займёмся подготовкой. К видео приложен архив со стартовым кодом проекта (в субтитрах — CLIproject.zip). Скачайте его, распакуйте и откройте редактор кода в папке проекта. Автор, чтобы сэкономить время, это уже сделал: в редакторе у него открыт этот небольшой проект.

Советую заглянуть в файл README.md — там инструкции по настройке. Они объясняют два шага:

  • как записать ключ API в файл .env проекта;
  • как установить зависимости — с UV или без него.

После этой настройки стартовый проект можно сразу запускать.

Пояснение

Кроме ключа API, в .env проекта задана модель чата CLAUDE_MODEL. В архиве этого же проекта из курса Building with the Claude API там стоит claude-sonnet-4-5, а Claude Sonnet 4.5 устарела: 30 ноября 2026 её снимают с поддержки, и запросы к ней начнут завершаться ошибкой. Замените значение на действующую модель, например claude-sonnet-5-5 (на ноябрь 2026).

Запуск приложения

В терминале перейдите в папку проекта. У автора она называется MCP, и в ней лежат все файлы и папки проекта.

Если вы пользуетесь UV, запускайте так:

uv run main.py

Если UV у вас нет — так:

python main.py

Автор пользуется UV, поэтому запускает uv run main.py. После запуска должно появиться приглашение чата. Если спросить «What's one plus one?», ответ должен прийти довольно быстро.

На этом подготовка закончена. Теперь можно сосредоточиться на том, чтобы добавлять в приложение новые возможности.

Пояснение

  • С UV — как в видео. uv run ставит версии из uv.lock: anthropic 0.51.0 и mcp 1.8.0.
  • Без UV. pip install из README ставит последний anthropic. Начиная с версии 1.0 у messages.create() нет параметра temperature, а core/claude.py его передаёт — первый же вопрос закончится TypeError. Укажите "anthropic<1" или уберите temperature из params в core/claude.py.
  • MCP Python SDK 2.x. В нём FastMCP переименован в MCPServer, и импорт mcp.server.fastmcp в mcp_server.py падает с ModuleNotFoundError. README и uv.lock фиксируют mcp 1.8.0; если ставите пакеты иначе, ограничьте версию: mcp<2.
