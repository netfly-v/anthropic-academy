Computer use: автоматизация программ без API

Чему научитесь

Текстовый урок, около 9 минут

К концу урока вы сможете:

  • объяснить, кто на самом деле выполняет действия computer use и как устроен цикл со скриншотами;
  • изолировать рабочий стол в отдельном контейнере и подключить его к Claude через подкласс computer toolset и Tool Runner;
  • написать функцию confirm, чтобы клики и ввод текста одобрял человек;
  • решать, когда нужен computer use, а когда лучше MCP-сервер, API, командная строка или browser use tool.

На странице урока нет видео: текст и интерактивное упражнение.

В большинстве компаний есть хотя бы одна программа совсем без API. Инструменты из предыдущих уроков до неё не дотягиваются: им просто нечего вызывать.

У Meridian, вымышленной инженерной консалтинговой фирмы, такая программа есть. Это старый менеджер чертежей PlotDesk, тоже вымышленный. Каждую пятницу один сотрудник весь день прокликивает одни и те же экраны, чтобы выгрузить комплекты чертежей в PDF. У PlotDesk нет ни API, ни командной строки. Только окна и кнопки.

Computer use позволяет Claude работать с PlotDesk через эти самые окна и кнопки, как работал бы человек: смотреть на скриншоты и решать, куда кликнуть и какой текст ввести.

Meridian хочет, чтобы Claude выгрузил сегодняшний PDF-комплект чертежей по проекту MEG-2026-0142.

Кто выполняет каждое действие

Через API Claude никогда не подключается к рабочему столу. Всё, что выдаёт Claude, — ответ с вызовами инструментов. Ваша программа — это программа на Python, которая вызывает Messages API. Именно она выполняет каждое действие на рабочем столе и отправляет результат обратно.

Цикл выглядит так. Claude просит скриншот. Ваша программа делает его и отправляет обратно как изображение. Claude смотрит на него и присылает следующее действие — например, клик по заданным координатам или текст, который нужно ввести. Ваша программа выполняет действие, и цикл повторяется, пока задача не будет выполнена. Это тот же цикл инструментов, что у вас уже есть, только часть результатов — скриншоты.

На всю выгрузку у Meridian ушло семь действий.

Запускайте рабочий стол в отдельном контейнере

Claude реагирует на всё, что появляется на экране. Текст на веб-странице или на картинке может взять верх над вашими инструкциями или подтолкнуть Claude к ошибкам. Чтобы ограничить вред от одного неверного действия, выделите рабочему столу отдельный контейнер или виртуальную машину, где есть только то, что нужно для задачи. Настройте его так:

  • у каждой сессии свой отдельный контейнер;
  • в контейнере нет учётных данных и нет каталогов, примонтированных с хоста;
  • из контейнера доступны только те сетевые хосты, с которыми работает задача.

Ваша программа и ваш API-ключ остаются за пределами контейнера.

Напишите действия, а цикл пусть ведёт SDK

В SDK для Python и TypeScript есть класс, который называется computer toolset. Вы создаёте от него подкласс и пишете по одному методу на каждое действие, нужное задаче. Класс сам собирает для toolset запись в tools и пока находится в бете. В Python для него нужен SDK версии 1.12.0 или новее.

Meridian реализует три действия из toolset: screenshot, left_click и type. Любое действие, которое вы не реализовали, уходит в API как отключённое.

Каждый метод — одна строка, которая передаёт работу объекту backend. Это ваша собственная обёртка над тем, что управляет рабочим столом, например над VNC-клиентом или xdotool. Начать удобно с этого минимального примера с VNC на Python и TypeScript, но для продакшена он не предназначен.

Передайте экземпляр своего класса в tools вместе с промптом. Tool Runner, помощник из SDK, сам ведёт цикл, пока Claude не ответит без вызова инструмента.

На ноябрь 2026 года этот toolset доступен в Claude API, Amazon Bedrock, Claude Platform on AWS, Claude Models on Google Cloud (Google managed) и Microsoft Foundry. Какие модели его поддерживают, зависит от платформы. Приведённая ниже программа Meridian обращается к Claude API, поэтому на другой платформе возьмите клиент SDK и ID модели этой платформы. У некоторых более старых моделей, например у Claude Opus 4.7, есть только прежние бета-версии инструмента. Для них нужна другая запись в tools и бета-заголовок — заголовок запроса, который включает бета-функцию.

Пояснение

  • Что уходит в API. Класс собирает запись {"type": "computer_toolset_20260801"}, а нереализованные действия помечает в её configs как "enabled": false. В бете — класс SDK и Tool Runner (отсюда beta в вызове), а сам toolset в Claude API, по документации на ноябрь 2026, бета-заголовка не требует.
  • Прежняя версия. Для Claude Opus 4.7 это бета-инструмент computer_20251124 с заголовком computer-use-2025-11-24: один инструмент computer, действие — в поле action. В toolset каждое действие — отдельный инструмент: в блоке tool_use стоят, например, "name": "left_click" и "toolset_name": "computer".
  • Несколько действий за ход. В отличие от цикла в уроке, Claude может прислать в одном ответе серию действий (batch action), например клик, ввод и скриншот. Их выполняют по порядку, а после первой ошибки остаток хода пропускают; Tool Runner делает это сам (на ноябрь 2026).

Пусть клики и ввод текста одобряет человек

Создавая экземпляр, передайте функцию confirm. SDK вызывает её перед каждым действием. Если она возвращает True, действие выполняется. Любое другое значение отклоняет действие, и Claude сообщают, что его отклонил человек.

confirm видит действие и его входные данные, но не экран. А человек, который следит за рабочим столом, видит, что находится в той точке, куда Claude хочет кликнуть. Поэтому Meridian одобряет скриншоты автоматически, а каждый клик и каждое действие type отправляет своему оператору — человеку, который следит за рабочим столом.

Вот программа Meridian. Три имени в ней взяты из собственного кода Meridian, а не из SDK: backend, ask_operator и TASK. ask_operator показывает действие оператору и возвращает его ответ, а в TASK лежит промпт.

Упражнение. На странице урока программа дана в интерактивном упражнении: в ней создан подкласс computer toolset из SDK, и для каждой из пяти задач нужно выбрать строку, которая её выполняет. При неверном выборе показывают подсказку, а при верном — короткую заметку об этой части программы. Задачи идут по одной.

Выберите строку программы, которая выполняет эту задачу.

Задача 1 из 5. Вы хотите, чтобы человек одобрял каждый клик и каждый ввод текста до того, как они произойдут.

from anthropic import Anthropic
from anthropic.tools.computer import (
    BetaAbstractComputerToolset20260801,
    BetaScreenshotResult,
)

class PlotDeskToolset(BetaAbstractComputerToolset20260801):
    def __init__(self, backend, **options):
        super().__init__(**options)
        self.backend = backend

    def screenshot(self, context, input):
        return BetaScreenshotResult(data=self.backend.png_base64())

    def left_click(self, context, input):
        self.backend.click(input.coordinate)

    def type(self, context, input):
        self.backend.type(input.text)

def confirm(context):
    if context.member == "screenshot":
        return True
    return ask_operator(context.member, context.input.to_dict())

with PlotDeskToolset(backend, confirm=confirm) as toolset:
    runner = Anthropic().beta.messages.tool_runner(
        model="claude-opus-5-5", max_tokens=1024,
        tools=[toolset],
        messages=[{"role": "user", "content": TASK}],
    )
    final = runner.until_done()
print("".join(b.text for b in final.content if b.type == "text"))

Пояснение

Без confirm эта программа не запустится. По документации SDK (на ноябрь 2026), если класс реализует type, key или hold_key, конструктор требует передать confirm либо отключить эти действия в configs. Сам SDK никого не спрашивает: без confirm он выполнил бы любой вызов, включая клики. Отклонённый вызов возвращается Claude как ошибка с просьбой не повторять его, и работа продолжается. Функция Meridian по умолчанию спрашивает человека: оператору уходит всё, кроме screenshot, в том числе действия, добавленные позже.

Когда computer use уместен

Каждый скриншот остаётся в разговоре, поэтому каждый следующий шаг обходится дороже предыдущего. Так что если у программы есть MCP-сервер (сервис, который предоставляет Claude свои функции как инструменты), API или командная строка, пользуйтесь ими, а не computer use. Computer use — для программ, у которых ничего этого нет, как у PlotDesk.

Если задача не выходит за пределы веб-страниц, лучше подходит browser use tool. Он читает саму страницу и действует прямо на ней, и полный рабочий стол ему не нужен.

Главное

  • Claude просит действия, а выполняет их ваша программа;
  • рабочий стол запускается в отдельном контейнере для каждой сессии;
  • вы реализуете только те действия, которые нужны задаче;
  • функция confirm у Meridian отправляет каждый клик и каждое действие type на одобрение человеку;
  • если есть прямой интерфейс, используйте его, а computer use — когда его нет.
