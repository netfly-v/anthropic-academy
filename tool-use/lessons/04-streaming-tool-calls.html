Потоковые вызовы инструментов: без зависших индикаторов

Чему научитесь

Видео 3:24 и текст урока

К концу урока вы сможете:

  • описать, из каких событий складывается потоковый вызов инструмента: content_block_start, content_block_delta с input_json_delta и content_block_stop;
  • показывать пользователю выбранный инструмент, как только открылся его блок;
  • перевести цикл вызова инструментов с client.messages.create(...) на client.messages.stream(...) и получить готовый ответ через stream.get_final_message(), не меняя остальной код.

Видео и текст урока.

При потоковой передаче вызов инструмента приходит так: сначала имя инструмента, а затем по частям его входные данные — поэтому экран может показывать, что происходит. В видео рядом показаны две версии экрана Meridian — вымышленной инженерно-консалтинговой компании. Одна работает без потоковой передачи, другая — с ней. Демо смоделировано и идёт в три раза медленнее обычного.

Видео записано в сентябре 2026 года, код в нём использует Claude Sonnet 5 (claude-sonnet-5). На более новых моделях результаты могут отличаться.

Допустим, ваш пользователь восемь секунд смотрит на крутящийся индикатор загрузки. Так происходит потому, что ваш цикл вызова инструментов отправляет каждый запрос, ждёт и получает обратно уже готовый ответ.

За это время Claude выбирает инструмент и пишет для него входные данные, ваш код запускает инструмент, а Claude пишет ответ. Ваш код видит каждый ответ только тогда, когда он готов целиком, поэтому интерфейсу нечего показать, пока Claude пишет.

Именно с этим сейчас столкнулась Meridian. Её агент поддержки написан на Python и отвечает на вопросы сотрудников о проектах. Когда сотрудник спрашивает «What's the status of the pump station job?» («Как продвигается проект насосной станции?»), на экране висит «thinking...», пока не придёт ответ.

Потоковая передача меняет то, что видит этот сотрудник. С потоковой передачей ваш код получает ответ по частям, ещё до того, как он будет готов. Поэтому на экране Meridian может появиться «Looking up project...», как только Claude выберет инструмент.

Как выглядит потоковый вызов инструмента

В том месте, где ваш цикл отправляет запрос, замените client.messages.create(...) на client.messages.stream(...). Тогда ответ будет приходить серией server-sent events — небольших JSON-сообщений, у каждого из которых есть поле type.

Ответ состоит из блоков содержимого (content blocks, или просто блоков): по одному блоку на каждый отрезок текста Claude и по одному на каждый вызов инструмента. У блока вызова инструмента тип tool_use. Современные модели могут добавлять ещё и блоки размышлений (thinking), но код этого урока их не учитывает.

Представьте, что друг по телефону диктует вам номер. Сначала он говорит, чей это номер: «Вот номер сантехника». Потом читает его по нескольку цифр, останавливаясь там, где захочет. А в конце говорит: «Всё».

Блок вызова инструмента приходит так же, как этот номер. Одно событие его открывает, одно или несколько наполняют, и одно закрывает. Вот события вызова инструмента у Meridian.

{"type": "content_block_start", "index": 0,
 "content_block": {"type": "tool_use", "id": "toolu_01",
                   "name": "lookup_project_status", "input": {}}}
{"type": "content_block_delta", "index": 0,
 "delta": {"type": "input_json_delta", "partial_json": "{\"project_"}}
{"type": "content_block_delta", "index": 0,
 "delta": {"type": "input_json_delta", "partial_json": "id\": \"MEG-2"}}
{"type": "content_block_delta", "index": 0,
 "delta": {"type": "input_json_delta", "partial_json": "026-0142\"}"}}
{"type": "content_block_stop", "index": 0}

Пояснение

  • Сборка входных данных. В видео есть правило для «сырых» событий: фрагменты partial_json режутся где угодно, даже посреди ключа или значения, а бывают и пустыми. Копите их в буфере и разбирайте JSON только после content_block_stop; если вызовов в ответе несколько, держите отдельный буфер для каждого index. Запускать инструмент пора, когда message_delta в конце ответа принесёт stop_reason: "tool_use". client.messages.stream(...) собирает фрагменты сам.
  • Паузы. На ноябрь 2026 API по умолчанию придерживает каждую пару «ключ — значение» из input, пока она не будет готова целиком, поэтому между событиями бывают паузы. Поле eager_input_streaming: true в описании инструмента включает fine-grained tool streaming: фрагменты идут сразу, но без проверки, и собранный JSON может оказаться невалидным.

Показывайте выбранный инструмент, как только открылся его блок

Имя инструмента приходит в content_block_start — первом событии блока. Как только это событие придёт, ваш код может обновить строку состояния — ту единственную строку текста, которую интерфейс показывает, пока пользователь ждёт.

У Meridian есть небольшой словарь STATUS, который сопоставляет имени каждого инструмента понятные пользователю слова, так что lookup_project_status превращается на экране в «Looking up project...».

Соберите потоковый запрос

Когда поток закончится, вызовите stream.get_final_message() и получите готовый ответ — объект того же вида, что возвращает client.messages.create(...). Поэтому остальная часть цикла вызова инструментов остаётся прежней.

Вот потоковый запрос Meridian. on_status — функция, которую вы пишете сами: она выводит переданный ей текст в строку состояния.

На странице урока здесь упражнение: в цикле на Python, который обрабатывает события потокового вызова инструмента, нужно для каждой из пяти задач — например, открыть поток или показать выбранный инструмент — выбрать строку, которая её выполняет. При неверном выборе появляется подсказка, при верном строка подсвечивается и объясняется её роль. Задание: «Выберите строку программы, которая выполняет эту задачу».

STATUS = {
    "lookup_project_status": "Looking up project...",
    "get_site_weather": "Checking site weather...",
}

with client.messages.stream(
    model="claude-sonnet-5", max_tokens=1024,
    tools=tools, messages=messages,
) as stream:
    for event in stream:
        if event.type == "content_block_start":
            if event.content_block.type == "tool_use":
                on_status(STATUS[event.content_block.name])
    resp = stream.get_final_message()

Пять задач упражнения, подсказки и верные строки с пояснениями:

  1. Нужно вызвать функцию вывода строки состояния и передать ей слова для инструмента, который выбрал Claude. Подсказка: on_status — функция, которая выводит текст в строку состояния. Верная строка — on_status(STATUS[event.content_block.name]), «Показать выбранный инструмент»: когда открывается блок tool_use, STATUS превращает его имя в слова, а on_status показывает их пользователю.
  2. Нужно, чтобы код срабатывал только при открытии блока, а не когда блок наполняется или закрывается. Подсказка: у каждого события есть поле type, и один из типов открывает блок. Верная строка — if event.type == "content_block_start":, «Поймать открытие блока»: это событие открывает блок и приходит для него первым.
  3. Нужно, чтобы остальной цикл работал как раньше, с объектом того же вида, что возвращал create. Подсказка: когда поток заканчивается, вспомогательный метод возвращает готовый ответ. Верная строка — resp = stream.get_final_message(), «Получить готовый ответ»: в resp лежит то, что раньше возвращал create, и дальше цикл идёт как прежде.
  4. Нужно изменить способ отправки запроса, сохранив настройки, которые были у старого запроса. Подсказка: поток открывает вспомогательный метод SDK, и он принимает настройки старого запроса. Верная строка — with client.messages.stream(, «Открыть поток»: метод принимает те же настройки, что и старый запрос, а цикл for затем получает события по одному.
  5. Нужно, чтобы строка состояния не менялась, когда открывается блок с текстом Claude. Подсказка: у блока вызова инструмента и у текстового блока разные типы. Верная строка — if event.content_block.type == "tool_use":, «Пропустить текстовые блоки»: блок с текстом Claude открывается так же, и эта проверка пропускает его, не трогая строку состояния.

Пояснение

  • Статус по входным данным. В демо из видео строка «Checking MEG-2026-0142» появляется, как только во входных данных набрался номер проекта, — ещё до запуска инструмента. На ноябрь 2026 в Python SDK для этого есть событие input_json: кроме очередного partial_json в нём лежит snapshot — уже разобранная часть входных данных, например event.snapshot.get("project_id").
  • Модель. На ноябрь 2026 claude-sonnet-5 по-прежнему доступна, но самая новая модель Sonnet — claude-sonnet-5-5.

Главное

  • Потоковый вызов инструмента приходит так: сначала имя инструмента, затем по частям его входные данные.
  • Как только пришло content_block_start, покажите выбранный инструмент словами, понятными пользователю.
  • stream.get_final_message() возвращает готовый ответ, поэтому остальная часть цикла вызова инструментов не меняется.
