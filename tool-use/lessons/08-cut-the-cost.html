Как снизить цену работы с инструментами

Чему научитесь

Видео 3:45 и текст урока

К концу урока вы сможете:

  • находить по usage.input_tokens, какая часть запроса стоит дороже всего;
  • включать programmatic tool calling: инструмент code execution, поле allowed_callers и ID контейнера;
  • кешировать определения инструментов одной строкой с cache_control и помнить о подвохах кеша;
  • выбирать между двумя приёмами по тому, из чего складываются входные токены.

Видео и текст урока.

Агент, который пользуется инструментами, в каждом запросе отправляет всё заново. Programmatic tool calling и prompt caching сокращают разные части его расходов.

Демо в этом видео записано в сентябре 2026 года на Claude Sonnet 5 (claude-sonnet-5). На более новых моделях результаты могут отличаться.

Агент с инструментами в каждом запросе отправляет всё заново, поэтому стоимость его работы растёт с каждым вызовом инструмента. Каждый запрос содержит определения инструментов, системный промпт, вопрос и все результаты инструментов, полученные к этому моменту. Это его входные токены, и каждый из них оплачивается.

Эту стоимость снижают и programmatic tool calling, и prompt caching.

Meridian — вымышленная инженерно-консалтинговая компания, в которой 40 инженеров. Её агенту задали один вопрос: у каких инженеров загрузка в июне 2026 года была ниже 70%? У агента было два инструмента: list_employees возвращает список сотрудников, а get_employee_hours — табель одного инженера.

Чтобы ответить на этот вопрос, агенту понадобилось 42 запроса и 1 124 799 входных токенов. Весь прогон обошёлся в $2,29 за токены.

Измеряйте входные токены каждого запроса

Выводите usage.input_tokens каждый раз, когда приходит ответ: эти числа показывают, на что уходят деньги.

resp = client.messages.create(...)
print(resp.usage.input_tokens, "input tokens")

Агент Meridian работает в классическом цикле: в каждом ответе запрашивается один вызов инструмента. Вот два его замера.

ЗапросЧто в нёмВходные токены
Запрос 1Определения инструментов, системный промпт и вопрос606
Запрос 37То же плюс 36 предыдущих результатов инструментов47 905

В запросе 1 — только то, что отправляется с каждым запросом. В следующие запросы добавляются вызовы инструментов и их результаты. Сравните два числа, чтобы увидеть, какая часть выросла.

Уберите результаты инструментов из того, что читает Claude

При programmatic tool calling (программном вызове инструментов) Claude пишет скрипт, который вызывает ваши инструменты, а инструмент code execution запускает этот скрипт в контейнере. До Claude доходит только то, что скрипт выводит. Все 40 табелей Meridian остаются у скрипта, а Claude получает его короткий вывод.

Сначала проверьте свои инструменты и модель. На октябрь 2026 года programmatic tool calling не поддерживает инструменты с strict: true. Не поддерживает он и disable_parallel_tool_use — настройку tool_choice, которая ограничивает Claude одним вызовом инструмента в каждом ответе. А через tool_choice нельзя заставить Claude вызвать инструмент из скрипта.

Claude Haiku 4.5 эту возможность не поддерживает. Она работает в Claude API, Claude Platform on AWS и в развёртываниях Microsoft Foundry, размещённых у Anthropic.

Чтобы включить programmatic tool calling, нужны четыре изменения.

  1. Добавьте инструмент code execution в список tools.
  2. Отметьте инструменты, которые может вызывать скрипт. Добавьте каждому из них поле allowed_callers и укажите в нём инструмент code execution версии code_execution_20260120 или новее.
  3. Возвращайте ID контейнера. Берите его из каждого ответа, который остановился на вызове инструмента, и отправляйте в запросе, который возвращает результаты ваших инструментов.
  4. Опишите результат каждого инструмента. Укажите в описании структуру результата: скрипту нужно его разобрать. Вот описание get_employee_hours у Meridian.

Returns one engineer's hours for the month as JSON: {"name": str, "billable_hours": float, "utilization": float 0-1}

Вот цикл Meridian после этих изменений.

CODE_EXECUTION = "code_execution_20260120"
TOOLS = [
    {"type": CODE_EXECUTION, "name": "code_execution"},
    {**LIST_EMPLOYEES, "allowed_callers": [CODE_EXECUTION]},
    {**GET_EMPLOYEE_HOURS, "allowed_callers": [CODE_EXECUTION]},
]

messages = [{"role": "user", "content": QUESTION}]
container = None
while True:
    resp = client.messages.create(
        model="claude-sonnet-5", max_tokens=4096,
        tools=TOOLS, messages=messages, container=container,
    )
    print(resp.usage.input_tokens, "input tokens")
    if resp.stop_reason not in ("tool_use", "pause_turn"):
        break
    container = resp.container.id
    messages.append({"role": "assistant", "content": resp.content})
    if resp.stop_reason == "tool_use":
        messages.append({"role": "user", "content": run_tools(resp)})
print("".join(b.text for b in resp.content if b.type == "text"))
  • LIST_EMPLOYEES и GET_EMPLOYEE_HOURS — определения инструментов Meridian.
  • Ваша собственная функция run_tools выполняет каждый вызов инструмента и возвращает результаты.
  • При pause_turn цикл отправляет ответ обратно и продолжает работу.

Когда скрипт вызывает инструмент, stop_reason ответа равен "tool_use". Ваш код выполняет инструмент, и результат уходит скрипту, а не Claude. Скрипт может запускать инструменты параллельно, поэтому в одном ответе может оказаться несколько вызовов инструментов.

Вот тот же вопрос, решённый обоими способами.

ПрогонЗапросыВызовы инструментовВходные токеныСтоимость токенов
Классический цикл42411 124 799$2,29
Programmatic tool calling34128 486$0,0667

В обоих прогонах использовались один и тот же вопрос, одни и те же инструменты и claude-sonnet-5. Стоимость рассчитана по тарифам на сентябрь 2026 года, а время работы code execution оплачивается отдельно от токенов.

Programmatic tool calling подходит для независимых друг от друга обращений к данным. Пользы от него мало, когда Claude должен обдумать каждый результат, прежде чем сделать следующий вызов инструмента.

Пояснение

  • Почему запросов три. Судя по цифрам, скрипт сначала вызвал list_employees, затем запросил 40 табелей параллельно, одним ответом. Каждая пауза скрипта — отдельный запрос вашего цикла.
  • Что идёт в счёт. На ноябрь 2026 результаты программных вызовов не засчитываются во входные и выходные токены: считаются только итоговый вывод code execution и ответ Claude.
  • Ответ на паузу. Сообщение с результатами для скрипта должно содержать только блоки tool_result, без текста, а без ID контейнера API его отклонит. На ноябрь 2026 вызов, который ждёт результата, завершается ошибкой TimeoutError внутри скрипта примерно через 4 минуты (в видео — «через несколько минут»).

Кешируйте повторяющиеся определения инструментов

Когда включён prompt caching, API сохраняет префикс вашего запроса — часть до отмеченной вами точки кеширования. Повторное чтение этого префикса обходится гораздо дешевле.

У второго агента Meridian 14 инструментов, и их определения занимают 3 305 токенов, которые заново отправляются с каждым запросом.

Отметьте точку кеширования, добавив cache_control к последнему инструменту, — и в кеш попадёт весь список. Это одна строка:

TOOLS[-1]["cache_control"] = {"type": "ephemeral"}

На Claude Sonnet 5 чтение префикса стоит десятую часть обычной цены входных токенов. Запись обходится в 1,25 раза дороже обычных входных токенов.

Кешированный префикс по умолчанию живёт пять минут, и каждое использование продлевает этот срок. Если запросы идут реже, добавьте "ttl": "1h" в cache_control, чтобы префикс хранился час. Запись часового кеша стоит вдвое дороже обычных входных токенов.

Meridian прогнала одни и те же восемь вопросов с кешем и без него. Общая стоимость входных токенов снизилась с $0,0554 до $0,0154.

При автоматическом кешировании вы добавляете одно поле cache_control на верхний уровень запроса, а точку кеширования ставит за вас API.

Когда кеш включён, следите за тремя вещами:

  1. Измените любое определение инструмента — и потеряете весь кеш.
  2. На Sonnet 5 кешированный префикс должен быть не короче 1 024 токенов. Если он короче, ничего не кешируется, и никакая ошибка об этом не сообщит.
  3. С включённым кешем в input_tokens не входит кешированный префикс, поэтому настоящее число входных токенов запроса — это сумма input_tokens, cache_read_input_tokens и cache_creation_input_tokens.

Пояснение

Уточнение из видео к первому пункту: префикс кешируется в порядке tools → system → messages, и изменение на любом уровне сбрасывает кеш этого уровня и всех следующих. Поэтому правка определения инструмента обнуляет весь кеш, а правка системного промпта кеш инструментов сохраняет. Понять, что кеш не сработал (второй пункт), можно по usage: если cache_creation_input_tokens и cache_read_input_tokens оба равны 0, ничего не закешировано.

Сочетайте приёмы там, где они подходят

Добавляйте их в таком порядке.

  1. Начните с кеширования. Это одна строка.
  2. Проверьте programmatic tool calling. Прогоните часть обычного трафика с allowed_callers и без него, затем сравните оплаченные входные токены каждого прогона.

Для каждого из двух запросов Meridian, приведённых ниже, найдите часть, в которой больше всего входных токенов, и выберите приём, который её сокращает.

Упражнение: полосы на двух карточках показывают, из каких источников складываются входные токены — для одного записанного запроса в конце долгого прогона агента и для среднего запроса из прогона другого агента. Нужно выбрать, что экономит больше всего: programmatic tool calling, prompt caching или ни то ни другое, — и упражнение прокомментирует выбор.

Пояснение

На странице урока это интерактивное упражнение с отзывом. Ответы: в первой карточке 99% токенов — накопленные результаты независимых вызовов, их убирает из контекста programmatic tool calling. Во второй 95% — повторяющиеся определения инструментов, их удешевляет prompt caching (3 305 токенов больше минимума в 1 024).

Главное

  • Каждый запрос отправляет всё заново, поэтому за старые результаты инструментов вы платите снова и снова.
  • Выводите usage.input_tokens каждый раз, когда приходит ответ, — так вы узнаете, какая часть запроса стоит дороже всего.
  • Начните с кеширования. Добавьте cache_control к последнему инструменту в списке.
  • Если вызовы инструментов не зависят друг от друга, настройте programmatic tool calling с инструментом code execution и allowed_callers. Отправляйте ID контейнера с каждым следующим запросом.
