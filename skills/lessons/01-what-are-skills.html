Что такое skills

Видео, около 3 минут

Видео показывает идею целиком: вместо того чтобы каждый раз заново объяснять, как смотреть pull request или как писать сообщение коммита, вы записываете инструкцию один раз. Claude Code сам подхватывает её, когда задача подходит.

Коротко

  • Skill — папка с инструкциями. Главный файл называется SKILL.md. В начале файла, во frontmatter, есть имя и описание.
  • Claude сравнивает ваш запрос с описаниями и включает те skills, которые подходят по смыслу.
  • Личные skills лежат в ~/.claude/skills и ездят с вами по всем проектам. Skills проекта лежат в .claude/skills внутри репозитория и достаются всем, кто его клонирует.
  • Skill грузится по делу. CLAUDE.md попадает в каждый разговор. Slash-команду нужно вызвать самому.
  • Если вы уже третий раз объясняете Claude одно и то же, это кандидат в skill.

Из чего состоит skill

Каждый раз, когда вы заново рассказываете стандарты команды, формат ревью или шаблон коммита, вы тратите контекст на повтор. Skill записывает это знание один раз, а Claude применяет его, когда тема всплывает.

Описание — это критерий выбора. Вы просите «посмотри этот PR», Claude сопоставляет фразу с описаниями доступных skills и открывает подходящий. Ниже frontmatter идёт сама инструкция: чеклист, формат, ограничения.

---
name: pr-review
description: Reviews pull requests for code quality. Use when reviewing PRs or checking code changes.
---

Имя говорит, как skill называется. Описание говорит, когда его брать. Всё, что после второй черты ---, Claude читает уже после того, как skill выбран.

Пояснение

Frontmatter — это YAML между двумя строками --- в самом верху файла. Claude Code читает его как метаданные, только если первая строка файла — именно ---. Если перед ней есть пустая строка или комментарий, весь файл, включая «шапку», считается обычным текстом инструкции, и поля не сработают.

При старте в контекст попадают только имя и описание, а не весь чеклист. Поэтому длинный skill не занимает окно контекста, пока вы не попросили соответствующую задачу. Окно контекста — это ограниченный объём текста, который модель видит за один ход: чем больше туда заранее положить «на всякий случай», тем меньше места остаётся на код и ваш вопрос.

Где лежат skills

  • Личные — ~/.claude/skills в домашней папке. Стиль коммитов, как вы любите объяснения кода, ваш личный шаблон документации. На Windows это C:/Users/<ваш-пользователь>/.claude/skills.
  • Проектные — .claude/skills в корне репозитория. Их коммитят вместе с кодом. Сюда кладут стандарты команды: как ревьюить, какие шрифты и цвета у продукта, как устроены доки.

Кто склонировал репозиторий, тот получил проектные skills без отдельной установки.

Пояснение

Папка skill — это каталог, а не одинокий файл в корне skills. Правильно: .claude/skills/pr-review/SKILL.md. Файл SKILL.md, лежащий прямо в .claude/skills/SKILL.md, Claude Code не подхватит как skill. Имя файла строгое: SKILL заглавными, расширение md строчными.

Skills, CLAUDE.md и slash-команды

У Claude Code несколько способов поменять поведение. Skill отличается тем, что он автоматический и привязан к задаче.

  • CLAUDE.md загружается в каждый разговор. «В этом проекте TypeScript только в strict mode» — это сюда.
  • Skill загружается, когда запрос совпал. Чеклист ревью не нужен, пока вы чините баг. Он появится, когда вы попросите ревью.
  • Slash-команду нужно набрать явно, например /pr-review. Skill Claude может включить сам, когда узнаёт ситуацию. При этом skill тоже можно вызвать вручную через / и имя каталога.

Пояснение

В актуальном Claude Code старые файлы команд из .claude/commands/ и skills делают одно и то же: оба дают команду вида /имя. Разница в возможностях. У skill есть своя папка для скриптов и справок, и Claude может подключить его сам по описанию. Команды из commands по-прежнему работают, но для нового материала удобнее skill.

Когда skill уместен

  • стандарты код-ревью команды;
  • формат сообщений коммита;
  • гайдлайны бренда;
  • шаблоны определённого вида документации;
  • чеклист отладки конкретного фреймворка.

Правило простое: если вы повторяете Claude одно и то же, это уже skill, который ещё не записан. Постоянные правила проекта оставьте в CLAUDE.md. Процедуру, которая нужна иногда и занимает много текста, вынесите в skill.
