Собираем skill с нуля

Видео, около 4 минут

В ролике делают личный skill для описаний pull request: он работает во всех ваших проектах. Заодно показывают, какой skill побеждает, если имена совпали.

Коротко

  • Skill — каталог с SKILL.md: метаданные сверху, инструкции снизу.
  • На старте Claude читает только имя и описание, потом сравнивает запрос с описаниями по смыслу.
  • Перед тем как втянуть полный текст в контекст, Claude спрашивает подтверждение.
  • При одинаковом имени побеждает: Enterprise, затем Personal, затем Project, затем Plugins.
  • Правите SKILL.md, чтобы обновить. Удаляете каталог, чтобы убрать. После изменений перезапустите Claude Code.

Личный skill для описания PR

Имя каталога совпадает с именем skill. Создайте папку в личной директории:

mkdir -p ~/.claude/skills/pr-description

Внутри — SKILL.md. Описание должно звучать так, как вы сами просите эту работу.

---
name: pr-description
description: Writes pull request descriptions. Use when creating a PR, writing a PR, or when the user asks to summarize changes for a pull request.
---

When writing a PR description:

1. Run `git diff main...HEAD` to see all changes on this branch
2. Write a description following this format:

## What
One sentence explaining what this PR does.

## Why
Brief context on why this change is needed

## Changes
- Bullet points of specific changes made
- Group related changes together
- Mention any files deleted or renamed

Имя идентифицирует skill. Описание — критерий совпадения. Текст после второго --- Claude выполняет, когда skill уже выбран.

Пояснение

В личном или проектном skill команда, которую вы набираете после /, берётся из имени каталога, а не из поля name. Поле name здесь — подпись в списке. Каталог pr-description даёт команду /pr-description. В плагине поле name как раз меняет последнюю часть команды. Поэтому для своего первого skill проще держать имя папки и поле name одинаковыми: меньше путаницы.

Как проверить

Список skills собирается при запуске сессии. После создания файла перезапустите Claude Code и спросите, какие skills доступны. В списке должно появиться pr-description.

Дальше сделайте изменения на ветке и скажите что-то вроде «напиши описание PR по моим изменениям». Claude отметит, что использует skill, посмотрит diff и соберёт текст по вашему шаблону.

Как происходит совпадение

При старте Claude Code обходит места, где лежат skills, но в память кладёт только имя и описание. Полный файл ещё не читается.

Когда вы отправляете сообщение, запрос сравнивается с описаниями. Совпадение смысловое, а не по точному слову. Фраза «объясни, что делает эта функция» может задеть skill с описанием «explain code with visual diagrams», потому что намерение общее.

После совпадения Claude просит подтвердить загрузку. Так вы видите, какой текст сейчас войдёт в контекст. После согласия читается весь SKILL.md, и Claude следует ему.

Пояснение

Семантическое совпадение значит: модель смотрит на смысл, а не на точное вхождение ключевого слова. Если в описании только «helps with docs», запрос «поправь README в разделе установки» может не зацепиться — слишком широко и не про тот момент. Рабочее описание отвечает на два вопроса сразу: что skill делает и в каких формулировках его звать. Если одна из ваших обычных фраз не срабатывает, допишите её в description почти дословно.

Подтверждение нужно, потому что тело skill может быть длинным. Вы решаете, тратить ли на него контекст именно сейчас. Сам вызов через /pr-description тоже загружает текст, но уже без угадывания: вы назвали skill прямо.

Чей skill побеждает

Если в склонированном репозитории есть skill с тем же именем, что и ваш личный, победитель задан порядком:

  1. Enterprise — управляемые настройки организации, самый высокий приоритет.
  2. Personal — ~/.claude/skills.
  3. Project — .claude/skills в репозитории.
  4. Plugins — установленные плагины, самый низкий приоритет.

Корпоративный code-review перекроет ваш личный code-review. Организация может закрепить обязательный стандарт, а личные skills остаются для всего, что не конфликтует по имени. Чтобы не сталкиваться, называйте skills конкретно: не review, а frontend-review или backend-review.

Пояснение

Приоритет сравнивает одинаковые имена, а не «похожие» skills. frontend-review и code-review живут рядом: оба могут сработать на один запрос, если описания пересекаются. Тогда проблема уже не в иерархии, а в слишком похожих описаниях. Иерархия отвечает только на вопрос «какой файл с этим именем настоящий».

В документации Claude Code есть ещё вложенные skills: .claude/skills внутри подпапки монорепозитория подхватывается, когда сессия работает с файлами этой подпапки. Для первого skill это не нужно, но полезно знать, что «проектный» уровень не всегда один на весь репозиторий.

Правка и удаление

Обновление — это правка SKILL.md. Удаление — удаление каталога skill. Пока сессия не перезапущена, Claude Code продолжает видеть тот список, который собрал на старте.
