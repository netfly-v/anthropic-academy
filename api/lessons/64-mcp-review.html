На странице урока только видео. Ниже — его содержание по субтитрам.

Смотреть урок на Skilljar MCP review · 4:12

Проект готов, но прежде чем идти дальше — краткий итог по трём примитивам сервера, которые мы изучили: инструментам, ресурсам и промптам. Особенно интересно, какая часть приложения отвечает за запуск каждого из них: кто на самом деле их запускает и кому они приносят пользу.

Кто управляет каждым примитивом

  • Инструменты управляются моделью (model-controlled). Только Claude решает, когда запустить инструмент.
  • Ресурсы управляются приложением (app-controlled). Код вашего приложения решает, что ему нужны данные ресурса, выполняет запрос и как-то использует результат — например, показывает в интерфейсе. В нашем проекте мы получали ресурс, чтобы показать список вариантов автодополнения, и ещё раз — чтобы дополнить промпт. И то и другое — код приложения, который написали мы.
  • Промпты управляются пользователем (user-controlled). Пользователь решает, когда запустить промпт: нажимает кнопку или пункт меню в интерфейсе или вводит слэш-команду, как у нас.

Зачем это подчёркивать — чтобы понимать назначение каждого примитива:

  • если нужно добавить Claude возможности — скорее всего, нужны инструменты в вашем MCP-сервере (или инструменты чужого сервера через ваш MCP-клиент);
  • если нужно получить данные в приложение, чтобы показать их в интерфейсе или похожее, — скорее всего, нужен ресурс;
  • если нужно реализовать заранее заданный сценарий работы — смотрите в сторону промптов.

Примеры в Claude.ai

Все эти идеи можно увидеть в официальном интерфейсе Claude.ai.

  • Промпт. Под полем ввода чата есть кнопки с готовыми сценариями. Нажимаешь одну, выбираешь пример — и сразу начинается чат. Это действие пользователя: он решил запустить сценарий, и используется заранее написанный и, вероятно, оптимизированный промпт. Чтобы сделать такой список кнопок, в MCP-сервере понадобился бы набор промптов.
  • Ресурс. Кнопка «+» открывает пункт «Add from Google Drive»: появляется список документов, которые можно добавить в чат как контекст. Знать, какие документы показать в списке, и при клике автоматически подставлять содержимое в контекст — это код приложения и элементы интерфейса. Чтобы реализовать такой список документов Google Drive, стоило бы сделать ресурс в MCP-сервере.
  • Инструмент. Если написать в чате «what is 3 squared? Use JavaScript to calculate the value», очевидно ожидается, что Claude как-то выполнит JavaScript — скорее всего, с помощью инструмента. Решение воспользоваться инструментом здесь на 100% за моделью. В MCP-сервере для этого стоило бы, как вы догадались, сделать инструмент.

Итого: три примитива сервера, и каждый предназначен для своей части приложения. Инструменты в основном служат модели, ресурсы — приложению, а промпты — пользователям. Это общие ориентиры, а не жёсткие правила — они нужны, чтобы понимать, когда какой примитив использовать в зависимости от того, что вы строите.

Пояснение

  • Это есть и в спецификации. Спецификация MCP прямо называет промпты «user-controlled» (пользователь явно выбирает их, например слэш-командой), а модель управления ресурсами и инструментами описана в тех же терминах: приложение и модель.
  • Шпаргалка для экзамена: «добавить действие, которое Claude выберет сам» → tool; «дать приложению данные для интерфейса или контекста» → resource; «готовый сценарий, который запускает пользователь» → prompt.
