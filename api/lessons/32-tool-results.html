Отправка результатов

Чему научитесь

Видео 9:22 и текст урока

К концу урока вы сможете:

  • выполнить функцию с аргументами из блока tool_use;
  • собрать блок tool_result с правильным tool_use_id;
  • сделать итоговый запрос и получить ответ с результатом инструмента.

Видео и текст урока.

Смотреть урок на Skilljar Sending tool results · 9:22

Когда Claude запросил вызов инструмента, нужно выполнить функцию и отправить результат обратно. Это завершает цикл tool use: Claude получает запрошенную информацию.

Запускаем функцию-инструмент

Когда Claude отвечает блоком вызова инструмента, вы извлекаете входные параметры и вызываете свою функцию. Параметры инструмента лежат здесь:

response.content[1].input

Это словарь аргументов, которые Claude хочет передать функции. Функция ждёт именованные аргументы, а не словарь, поэтому используем распаковку Python:

get_current_datetime(**response.content[1].input)

Блок tool_result

Выполнив функцию, нужно отправить результат Claude в блоке результата инструмента (tool result). Этот блок кладётся в сообщение пользователя и сообщает Claude, что произошло при выполнении инструмента.

Важные свойства блока результата:

  • tool_use_id — должен совпадать с id блока ToolUse, на который отвечает этот результат;
  • content — вывод инструмента, сериализованный в строку;
  • is_error — True, если произошла ошибка.

Несколько вызовов инструментов

Claude может запросить несколько вызовов в одном ответе. Например, на вопрос «What's 10 + 10 and what's 30 + 30?» Claude может ответить двумя отдельными блоками ToolUse.

У каждого вызова свой уникальный ID, и при отправке результатов нужно указывать эти ID. Так Claude знает, какой результат к какому запросу относится, даже если результаты пришли в другом порядке.

Собираем следующий запрос

Следующий запрос к Claude должен содержать всю историю разговора плюс новый результат инструмента. Структура такая:

messages.append({
    "role": "user",
    "content": [{
        "type": "tool_result",
        "tool_use_id": response.content[1].id,
        "content": "15:04:22",
        "is_error": False
    }]
})

Теперь история сообщений содержит:

  • исходное сообщение пользователя;
  • сообщение ассистента с блоком вызова инструмента;
  • сообщение пользователя с блоком результата.

Итоговый запрос

В следующем запросе нужно по-прежнему передавать схему инструмента, даже если вы не ждёте, что Claude снова его вызовет. Схема нужна Claude, чтобы понимать ссылки на инструмент в истории разговора.

client.messages.create(
    model=model,
    max_tokens=1000,
    messages=messages,
    tools=[get_current_datetime_schema]
)

Claude ответит итоговым сообщением, которое включает результаты инструмента в естественный ответ для пользователя. Цикл tool use завершён — вы дали Claude доступ к информации в реальном времени через свою функцию.

Пояснение

  • content[1] — только для этого примера. Здесь первым блоком идёт текст, вторым — вызов. Это не гарантировано: текста может не быть, вызовов может быть несколько. В рабочем коде блоки tool_use ищут по типу (см. урок «Реализация цикла»).
  • Строгие правила формата (по документации):
    • сообщение с результатами должно идти сразу после сообщения ассистента с вызовами — между ними ничего вставлять нельзя;
    • в этом сообщении блоки tool_result идут первыми, текст — только после них; текст перед результатами даёт ошибку 400;
    • при параллельных вызовах все результаты возвращают в одном сообщении пользователя. Если разнести их по разным сообщениям, Claude со временем перестаёт делать параллельные вызовы.
  • content — не только строка. Результат может быть и списком блоков: текст, изображение, документ.
  • Безопасность. Результаты инструментов часто содержат чужой текст (веб-страницы, письма, файлы), и в нём могут быть внедрённые инструкции (prompt injection). Документация советует держать такой контент именно в tool_result, а не переносить в system prompt.
