Видео и текст урока.

Смотреть урок на Skilljar Tool schemas · 4:39

Написав функцию-инструмент, нужно создать JSON-схему, которая сообщает Claude, какие аргументы ожидает функция и как ею пользоваться. Эта схема — документация, которую Claude читает, чтобы понять, когда и как вызывать ваши инструменты.

Что такое JSON Schema

JSON Schema не придумана специально для ИИ или вызова инструментов — это распространённая спецификация для проверки данных, которая существует уже много лет. Сообщество ИИ взяло её на вооружение, потому что ею удобно описывать параметры функций и проверять данные.

Полное описание инструмента состоит из трёх основных частей:

  • name — понятное, говорящее имя инструмента (например, "get_weather");
  • description — что делает инструмент, когда его использовать и что он возвращает;
  • input_schema — собственно JSON-схема аргументов функции.

Как писать хорошие описания

Описание инструмента очень важно: по нему Claude понимает, когда использовать вашу функцию. Рекомендации:

  • 3–4 предложения о том, что делает инструмент;
  • описать, когда Claude должен его использовать;
  • объяснить, какие данные он возвращает;
  • подробно описать каждый аргумент.

Простой способ получить схему

Вместо того чтобы писать JSON-схемы с нуля, можно поручить это самому Claude. Порядок такой:

  • скопируйте код функции-инструмента;
  • откройте Claude и попросите написать JSON-схему для вызова инструментов;
  • приложите в качестве контекста документацию Anthropic по tool use;
  • пусть Claude сгенерирует правильно оформленную схему по рекомендациям.

Промпт может быть примерно таким: «Write a valid JSON schema spec for the purposes of tool calling for this function. Follow the best practices listed in the attached documentation.»

Схема в коде

Когда Claude сгенерирует схему, скопируйте её в свой файл с кодом. Удобная схема именования:

def get_current_datetime(date_format="%Y-%m-%d %H:%M:%S"):
    if not date_format:
        raise ValueError("date_format cannot be empty")
    return datetime.now().strftime(date_format)

get_current_datetime_schema = {
    "name": "get_current_datetime",
    "description": "Returns the current date and time formatted according to the specified format",
    "input_schema": {
        "type": "object",
        "properties": {
            "date_format": {
                "type": "string",
                "description": "A string specifying the format of the returned datetime. Uses Python's strftime format codes.",
                "default": "%Y-%m-%d %H:%M:%S"
            }
        },
        "required": []
    }
}

Называйте схему по шаблону «имя функции + _schema» — так схемы легко держать в порядке и сопоставлять с функциями.

Типизация

Для лучшей проверки типов импортируйте и используйте тип ToolParam из библиотеки Anthropic:

from anthropic.types import ToolParam

get_current_datetime_schema = ToolParam({
    "name": "get_current_datetime",
    "description": "Returns the current date and time formatted according to the specified format",
    # ... rest of schema
})

Для работы это не обязательно, но так вы избежите ошибок типов при передаче схемы в API Claude, и код станет надёжнее.

Пояснение

  • Описание — главный фактор. Документация Anthropic называет подробные описания «by far the most important factor» качества работы с инструментами: что делает инструмент, когда его использовать и когда нет, что значит каждый параметр, какие есть ограничения. Минимум 3–4 предложения, для сложных инструментов больше. Описание в примере урока (одно предложение) — скорее минимальный вариант.
  • Имя инструмента должно соответствовать шаблону ^[a-zA-Z0-9_-]{1,128}$: латиница, цифры, _ и -.
  • strict: true. Если добавить в описание инструмента "strict": true, API гарантирует, что аргументы вызова точно соответствуют схеме (без пропущенных обязательных полей и неверных типов). Для этого у объектов схемы должны быть "additionalProperties": false и список required.
  • Другие рекомендации документации: объединять родственные действия в один инструмент с параметром action вместо множества мелких; добавлять префикс сервиса в имена (github_list_prs), когда инструментов много; для сложных входов можно добавить поле input_examples с примерами корректных вызовов.

Дальше

Схема готова — теперь отправим её в API и разберём новый вид ответа: сообщение из нескольких блоков.
