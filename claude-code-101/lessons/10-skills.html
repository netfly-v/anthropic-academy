Каждый раз, когда вы объясняете Claude стандарты кода своей команды, вы повторяетесь. На каждом ревью PR вы заново описываете, в каком виде хотите получить замечания. Для каждого сообщения коммита напоминаете Claude, какой формат вы предпочитаете. Skills избавляют от этого.

Что такое skill

Skill — это Markdown-файл, который один раз учит Claude что-то делать, а дальше Claude сам применяет это знание всякий раз, когда оно к месту. Skills для Claude — это папки с инструкциями, скриптами и ресурсами, которые агенты могут находить и использовать, чтобы работать точнее и эффективнее.

В Claude Code для этого есть файл SKILL.md. По описанию (description) Claude решает, использовать ли skill. Когда вы просите: «Сделай ревью этого PR», Claude сопоставляет вашу просьбу с описаниями доступных skills и находит skill для ревью. Claude читает вашу просьбу, сравнивает её с описаниями всех доступных skills и включает те, что подходят.

Где хранить skills

Хранить skills можно в нескольких местах — смотря по тому, кому они нужны. Личные skills лежат в домашней папке, в .claude/skills, и действуют во всех ваших проектах. Это ваши предпочтения: стиль сообщений коммитов, формат документации, то, как вам нравится получать объяснения кода. Skills проекта лежат в .claude/skills в корне репозитория. Кто клонирует репозиторий, автоматически получает и эти skills. Здесь живут стандарты команды — например, брендбук компании, предпочтительные шрифты и цвета, которые вы используете в веб-дизайне.

Пояснение

Skill — это папка с файлом SKILL.md: ~/.claude/skills/<имя>/SKILL.md для личных и .claude/skills/<имя>/SKILL.md для проекта. Во frontmatter файла главное — поле description: по нему Claude и выбирает skill, поэтому документация Claude Code (на ноябрь 2026) советует вписать туда слова, которыми вы обычно формулируете такую просьбу. Поле name необязательно — по умолчанию это имя папки.

Чем skills отличаются от CLAUDE.md и slash-команд

В Claude Code есть несколько способов настроить поведение. Skills выделяются тем, что срабатывают автоматически и привязаны к конкретной задаче. Файлы CLAUDE.md загружаются в каждый разговор. Если вы хотите, чтобы Claude всегда писал на TypeScript в strict mode, такому правилу место в CLAUDE.md. Skills же загружаются по требованию, когда соответствуют вашей просьбе. Заранее загружаются только имя и описание, поэтому skills не забивают всё окно контекста. Чеклист ревью PR не нужен в контексте, пока вы отлаживаете код. Он загрузится, когда вы действительно попросите ревью.

Slash-команды нужно набирать самому, skills — нет: Claude применяет их, когда узнаёт ситуацию. Лучше всего они подходят для специальных знаний, которые относятся к определённым задачам: стандарты ревью кода, которым следует ваша команда, форматы сообщений коммитов, которые вы предпочитаете, брендбук вашей организации. Если вы ловите себя на том, что раз за разом объясняете Claude одно и то же, — это skill, который ждёт, когда его напишут.

Хотите разобраться глубже? Загляните в наш отдельный курс: Introduction to agent skills.

Пояснение

  • Slash-команды и skills. Урок их противопоставляет, но по документации Claude Code (на ноябрь 2026) пользовательские slash-команды объединены со skills: skill по умолчанию можно вызвать и вручную — командой /имя-skill, а старые файлы из .claude/commands/ работают по-прежнему, и Claude может запускать их сам. Чтобы skill запускался только вручную, во frontmatter ставят disable-model-invocation: true.
