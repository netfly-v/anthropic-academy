Субагенты

Чему научитесь

Видео 2:48 и текст урока

К концу урока вы сможете:

  • объяснить, как субагенты берегут контекстное окно основного разговора: работают в собственном контексте и возвращают только сводку;
  • создать своего субагента, попросив об этом Claude, и выбрать, где будет лежать его файл: в .claude/agents/ или в ~/.claude/agents/;
  • назвать два способа дополнительно настроить субагента: постоянную память и предзагрузку skills.

Видео и текст урока.

Claude может поручать задачи субагентам: они разбивают задачу на части и выполняют эти части параллельно, а вам становится проще управлять контекстом. Каждый субагент работает в собственном изолированном контекстном окне.

Как это работает

Управлять контекстом в Claude Code важно. Значительную часть контекстного окна съедают, например, вызовы инструментов, которыми Claude изучает вашу кодовую базу, или веб-поиск, когда нужно что-то исследовать. А то, что Claude узнаёт по ходу такого изучения, не всегда относится к главной функции, которую вы разрабатываете.

Здесь и пригодятся субагенты. Claude запускает субагента для задачи вроде «изучи для меня эту кодовую базу». Субагент работает параллельно, в собственном контекстном окне, берёт на себя всё изучение, а закончив, подводит итог найденному и возвращает эту сводку Claude.

В результате вы получаете нужный ответ, а весь путь к нему не засоряет основной контекст.

Пояснение

В видео сказано, что субагент получает только системный промпт из своего файла и задачу от основного агента, а после работы его разговор удаляется. По документации Claude Code (на ноябрь 2026) он получает ещё и файлы CLAUDE.md, а его транскрипт сохраняется в отдельном файле, так что работу субагента можно возобновить. Исключения — встроенные субагенты Explore и Plan: они стартуют без CLAUDE.md, и возобновить их нельзя.

Создание своего субагента

Субагентов описывают в Markdown-файлах с YAML-frontmatter. Проще всего для начала поручить Claude написать субагента за вас. Опишите, какой субагент вам нужен и куда его сохранить:

Create a code-reviewer subagent in .claude/agents/ that reviews code for bugs and readability. Make it read-only.

Субагент из .claude/agents/ работает в текущем проекте, а из ~/.claude/agents/ — во всех ваших проектах. Если выбранной папки не было на момент запуска сессии, перезапустите Claude Code, чтобы новый субагент загрузился.

Claude придумает субагенту имя, описание и промпт. По ним же Claude будет понимать, когда вызывать этого субагента в ответ на ваши промпты.

Дальнейшая настройка

Субагентов можно настраивать и дальше. Вот самое интересное:

  • Постоянная память позволяет субагенту сохранять знания между разговорами. Это очень удобно, если вы постоянно используете его в одних и тех же проектах.
  • Предзагружайте skills в субагентов: добавьте ключ skills и перечислите в нём skills по именам. Учтите, что, в отличие от skills в основном разговоре, здесь skill загружается в контекст целиком.

Пояснение

  • «Только для чтения». Отдельного поля для этого во frontmatter нет (на ноябрь 2026): обычно в поле tools перечисляют одни инструменты чтения, например tools: Read, Grep, Glob. Вариант disallowedTools: Write, Edit убирает только эти два инструмента, а Bash и MCP-инструменты остаются.
  • Когда вызывается. Передать ли задачу субагенту, Claude решает по его полю description. Можно вызвать субагента и явно — упомянуть его в промпте через @.
  • Память. Её включает поле memory со значением user, project или local.

Итог

Держать контекстное окно чистым — один из лучших способов продуктивно работать с Claude Code. С субагентами можно запустить агента в фоне: он возьмёт на себя тяжёлую работу и вернёт в основное контекстное окно только ответ.
