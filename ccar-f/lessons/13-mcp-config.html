MCP в Claude Code: .mcp.json и несколько серверов

Простыми словами

Добавление сервера и области действия разобраны в уроках выше; здесь — четыре решения для команды с несколькими серверами.

Общий сервер — в .mcp.json, токен — в переменной окружения. Этот файл коммитят: его видит каждый, кто клонировал репозиторий, и он остаётся в истории git. Поэтому вместо токена в файл пишут ссылку на переменную:

"headers": { "Authorization": "Bearer ${INCIDENTS_TOKEN}" }

Claude Code подставляет значение из окружения того, кто запустил сессию: файл у всех один, а токен у каждого свой. Подстановка работает в полях command, args, env, url и headers.

Личный или пробный сервер — не в .mcp.json. Его добавляют с областью user (все ваши проекты) или local (только текущий проект, область по умолчанию). Обе записываются в ~/.claude.json в домашней папке: этот файл не попадает в git, и коллегам не нужно одобрять незнакомый сервер. На экзамене сервер «для себя» или «на пробу» — область user, хотя по документации (на ноябрь 2026) пробному серверу одного проекта больше подходит local; в обоих случаях неверен только общий .mcp.json.

Инструменты всех серверов доступны сразу. Claude Code создаёт по MCP-клиенту на каждый сервер, при подключении запрашивает у каждого список инструментов и отдаёт Claude общий набор с именами вида mcp__<сервер>__<инструмент>. Переключать серверы или заводить по агенту на сервер не нужно.

Каталог данных — ресурсом. Агент, который не знает, какие данные есть, гадает и раз за разом вызывает поиск с разными словами. Сервер может отдать оглавление — список документов с короткими описаниями — в виде ресурса с постоянным URI. Claude сам находит и читает ресурсы встроенными инструментами ListMcpResourcesTool и ReadMcpResourceTool, а пользователь может приложить ресурс к промпту через @. В курсах каталог docs://documents нужен для автодополнения у пользователя; здесь его читает сам Claude — и сразу видит, что есть.

Пример

Команда платёжного сервиса подключает к Claude Code три сервера: трекер инцидентов с доступом по токену, базу справочников только для чтения и сервер ранбуков — внутренних инструкций. За первую неделю:

  • токен трекера записан прямо в headers файла .mcp.json и попал в историю git;
  • тимлид добавил в тот же файл свой экспериментальный сервер диаграмм, и вся команда получила запрос одобрить его;
  • на вопрос «есть ли ранбук по откату платежа?» Claude пять раз вызвал search_runbooks с разными словами и не нашёл документ «Возврат транзакций».

Архитектор отзывает токен и пишет в файл ${INCIDENTS_TOKEN}. Тимлид переносит сервер диаграмм к себе: claude mcp add --scope user …. Сервер ранбуков получает ресурс runbooks://index с названиями и описаниями всех документов: Claude читает оглавление и сразу открывает «Возврат транзакций». Отдельный агент под каждый сервер не нужен.

Как это спрашивают

Ситуации — как в примере. Заманчивые неверные ходы:

  • токен прямо в .mcp.json («репозиторий же закрытый») — он навсегда останется в истории git;
  • .mcp.json в .gitignore или общий сервер у каждого в личных настройках — конфигурации расходятся, а новичок не получает ничего;
  • пробный сервер в общем .mcp.json — его навязывают всей команде;
  • правило в промпте «ищи, пока не найдёшь» или больше результатов поиска — агент всё равно не видит, что есть;
  • список документов в CLAUDE.md — его ведут вручную, и он устаревает, а ресурс сервер собирает сам;
  • субагент на каждый сервер или подключение серверов по очереди — лишняя сложность: все инструменты и так доступны одновременно.

Верные ходы: общий сервер — в .mcp.json с ${VAR}, личный — в ~/.claude.json, каталог — ресурсом, несколько серверов — вместе.

Курс vs экзамен

На экзамене инструменты всех подключённых серверов доступны Claude с начала сессии — так и отвечайте. В Claude Code 101 упомянут tool search: на ноябрь 2026 он включён по умолчанию, и на старте Claude получает только имена инструментов и инструкции серверов, а полное определение подгружает, когда инструмент понадобится. Вызвать по-прежнему можно любой инструмент любого сервера.
