Команды и поля skill

Домен 3 · подпункт 3.2

Что уже есть в курсах

  • Skills · Что такое skills — личные skills в ~/.claude/skills, проектные в .claude/skills; файлы .claude/commands/ по-прежнему работают
  • Skills · Первый skill — при одинаковом имени личный skill побеждает проектный
  • Skills · Настройка и несколько файлов — поля name, description, allowed-tools, model; чем allowed-tools отличается от disallowed-tools
  • Skills · Как делиться skills — проектные skills приходят вместе с git clone; плагины и корпоративный уровень
  • Claude Code · Skills для проверки — skill, закоммиченный в .claude/skills, получает вся команда
  • Claude Code 101 · Skills — slash-команды объединены со skills; disable-model-invocation

Простыми словами

Кто получит команду, решает папка. Команда — промпт в Markdown-файле, который запускают как /имя. Файл в .claude/commands/ лежит в репозитории: его коммитят, и после git pull команда есть у всех. Файл в ~/.claude/commands/ — только ваш, зато работает во всех ваших проектах.

Экзамен говорит о командах как об отдельном механизме. На ноябрь 2026 это старый однофайловый формат skill, и он работает: и .claude/commands/release.md, и .claude/skills/release/SKILL.md дают /release и понимают те же поля frontmatter; при совпадении имён побеждает skill.

Своя версия общего skill — копия в ~/.claude/skills/ под другим именем. Правка файла в репозитории уйдёт всем со следующим коммитом. Копия с прежним именем подменит у вас общий skill (личный побеждает проектный): его обновления до вас не дойдут, а /имя у вас и у коллег начнёт делать разное.

Три поля frontmatter.

  • context: fork — skill выполняется в отдельном субагенте, а в основной разговор возвращается только итог. Так в сессию не попадают ни длинный вывод (обход сотен файлов), ни черновые варианты (из пяти набросков вернётся один выбранный). Fork не копирует текущий разговор, поэтому в skill нужно задание, понятное без контекста. Поле agent выбирает субагента, например Explore, который только читает.
  • allowed-tools — список инструментов skill; на экзамене это ограничение, см. «Курс vs экзамен».
  • argument-hint — подсказка вроде [версия], которую разработчик видит, пока набирает команду. Аргументы подставляются в текст skill на место $ARGUMENTS.

Пример

У команды мобильного банка с тремя общими skills четыре проблемы:

  • map-services обходит монорепозиторий и оставляет в сессии сотни строк с путями — Claude теряет нить задачи. Решение: context: fork и agent: Explore, в тексте — задание и формат сводки; в сессию вернётся короткая таблица.
  • changelog запускают без номера версии и получают заметки за весь год. Решение: argument-hint: [версия], $ARGUMENTS на месте номера и строка «если версия не указана, спроси».
  • gen-migrations должен только создавать файлы, а однажды стёр старые миграции через Bash. Решение на экзамене — allowed-tools только с инструментами чтения и записи файлов, в Claude Code (на ноябрь 2026) — disallowed-tools: Bash.
  • Тимлид переделал changelog под себя прямо в репозитории, и формат поменялся у всех. Решение: откатить правку, свой вариант держать в ~/.claude/skills/changelog-short/.

Как это спрашивают

Ситуацию узнают по признаку:

  • «Нужно всем» — закоммиченный файл в .claude/commands/ или .claude/skills/. Неверно: копия у каждого в ~/.claude/ (копии расходятся, новичок её не получит) или процедура в README.
  • «Вывод skill забивает сессию» — context: fork. Неверно: «отвечай кратко» в тексте skill (работа всё равно идёт в сессии), /compact после каждого запуска, модель с большим контекстом.
  • «Забывают параметр» — argument-hint, а не напоминание в CLAUDE.md, которое будет загружаться в каждый разговор.
  • «Skill не должен делать опасного» — ограничение инструментов во frontmatter, а не «ничего не удаляй» в тексте: это просьба, а не запрет.
  • «Хочу по-своему, не мешая коллегам» — личная копия под другим именем, а не правка общего файла.

Общий принцип: то, что должно соблюдаться, задают расположением файла и полями frontmatter, а не просьбой в промпте.

Курс vs экзамен

  • allowed-tools. Экзамен считает его ограничением: skill может пользоваться только перечисленными инструментами. Так и отвечайте. В Claude Code (на ноябрь 2026) поле лишь снимает запрос подтверждения для этих инструментов в том ходе, где skill вызван, а остальные доступны по обычным правилам разрешений. Настоящее ограничение — disallowed-tools в skill или список tools у субагента, которого skill запускает через context: fork и agent.
  • argument-hint. На экзамене это поле запрашивает у разработчика обязательный параметр. В документации (на ноябрь 2026) это лишь подсказка при автодополнении: запуск без аргумента она не останавливает.
