Сессии: продолжить, разветвить или начать заново

Домен 1 · подпункты 1.3, 1.7

Что уже есть в курсах

  • Claude Code · Routines и headless — session_id из JSON-вывода claude -p и продолжение сессии через --resume.
  • Claude Code · Проверка автономных запусков — форк-субагент наследует историю разговора, поэтому «холодным» рецензентом не будет.
  • Claude Code 101 · Управление контекстом — /clear для чистого старта; то, что должно пережить сессию, — в CLAUDE.md.

Простыми словами

Сессия — сохранённый разговор агента: промпты, ответы, вызовы инструментов и их результаты. Вернувшись к ней, агент снова помнит прочитанные файлы и сделанные выводы. Файлы проекта сессия не хранит.

Ходов три.

  • Продолжить. claude --continue открывает последнюю сессию в текущей папке. Если задач несколько, дайте каждой сессии имя (claude -n имя при запуске или /rename в сессии) и возвращайтесь через claude --resume имя.
  • Разветвить. Форк — новая сессия с копией истории и собственным ID; исходная не меняется, обе можно продолжать независимо. В командной строке это --fork-session вместе с --resume или --continue, в сессии — /branch, в Agent SDK — resume плюс fork_session=True (Python) или forkSession: true (TypeScript). Форк копирует только разговор, а правки файлов видны всем сессиям в папке, поэтому форкам, которые пишут код, дают по отдельному worktree.
  • Начать заново со сводкой. Новая сессия получает в первом промпте структурированную сводку: что выяснено и чем подтверждено, решения и их причины, отвергнутые гипотезы, открытые вопросы, на какие файлы опираются выводы.

Почему не всегда продолжать? Вместе с историей возвращаются старые результаты инструментов. Если код менялся, в контексте остаются прежние версии файлов: новую Claude увидит, только снова прочитав файл, а выводы по старой сами не обновятся. Claude Code (на ноябрь 2026) добавляет в разговор заметку, если изменился на диске файл, который Claude раньше правил, но сделанные выводы она не перепроверяет. Сводка надёжнее: в ней только выводы и файлы, на которые они опираются, без старых копий кода, которые модель может принять за текущие.

Правило выбора:

  • изменений немного и вы знаете, какие именно, — продолжить по имени: первым же сообщением назвать изменённые файлы и суть правок, попросить перечитать только их;
  • прочитанное агентом описывает уже другой код (большой рефакторинг, неделя чужих коммитов) или сессия увязла в неудачных попытках — новая сессия со сводкой;
  • нужно сравнить два подхода на основе одного анализа — форк.

Пример

Команда выясняет, откуда берутся дубли push-уведомлений. В понедельник разработчик запускает claude -n push-dupes, агент читает модуль отправки, воркер повторов и настройки очереди и находит причину: после таймаута воркер повторяет уже прошедшую отправку.

Во вторник — claude --resume push-dupes. За ночь влили PR, который поменял retry_worker.py и queue.yaml. Первым же сообщением разработчик пишет об этом, просит перечитать оба файла и сказать, какие выводы ещё в силе. Остальные сорок файлов перечитывать незачем.

Исправить можно ключом идемпотентности в базе или дедупликацией в очереди. Разработчик дважды запускает claude --resume push-dupes --fork-session, и каждый форк на основе общего анализа готовит план своего способа.

Через две недели модуль отправки переписан на другую библиотеку, половина файлов переименована. Разработчик просит старую сессию записать сводку в файл, открывает новую, передаёт ей файл и велит сверить каждый вывод с текущим кодом.

Как это спрашивают

К анализу возвращаются после перерыва, за который код изменился, или хотят сравнить два решения. Соблазнительные неверные ходы:

  • Просто продолжить и надеяться, что агент заметит изменения. Старые результаты чтения остаются в истории, и какие выводы устарели, агент сам не узнает.
  • Исследовать всё заново. Дорого, когда изменились два файла из сорока.
  • Модель покрупнее или правило «всегда перепроверяй» в промпте. Устаревшие данные из контекста не исчезнут, а какие файлы изменились, знает тот, кто запускает сессию.
  • --continue, когда в папке несколько сессий. Откроется последняя, а не нужная.
  • Два подхода по очереди в одной сессии. Они смешиваются; нужен форк.
  • Новая сессия без сводки теряет выводы, а с полной копией старой истории тащит те же устаревшие данные.

Верный ход — по правилу выбора выше: всё решает, насколько прочитанное агентом ещё соответствует коду.

Документация

  • Manage sessions — имена (-n, /rename, --resume по имени), --continue, /branch и --fork-session, что восстанавливается при возобновлении.
  • CLI reference — флаги --resume, --continue, --fork-session, --name.
  • Work with sessions (Agent SDK) — continue, resume, fork_session/forkSession; сессия хранит разговор, а не файлы; результаты в промпт свежей сессии вместо переноса истории.
  • Common workflows — Resume previous conversations, параллельные сессии в worktree; новую версию файла Claude видит при следующем чтении.
  • Best practices: Steer the session — /clear и новый промпт с тем, что узнали; /rename и --resume для работы на несколько дней.
  • Modifying system prompts: Reminders Claude Code adds to the conversation — File-changed notes: заметка, что файл, который Claude правил, изменился на диске.
