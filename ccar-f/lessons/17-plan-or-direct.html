Plan mode или сразу делать

Домен 3 · подпункт 3.4

Что уже есть в курсах

  • Claude Code 101 · Первый промпт — что делает plan mode и почему он хорош для сложных многошаговых изменений.
  • Claude Code 101 · Цикл Explore → Plan → Code → Commit — исследование кода и план в plan mode, правка плана до первой строки кода, затем выполнение одобренного плана.
  • Claude Code · Долгие сессии — рамки большой задачи задают планом: поправить план дешевле, чем разгребать последствия.
  • API · Claude Code в работе — схема «контекст → план → реализация».

Простыми словами

Курсы объясняют, как планировать. Экзамен проверяет, нужен ли план вообще. Прямое выполнение (direct execution) — обычный промпт без plan mode: Claude сразу читает нужные файлы, правит и проверяет. Plan mode — сначала исследование и план без правок, затем ваше одобрение и только потом правки.

Правило выбора — два вопроса:

  1. Известно ли заранее, где менять код и как понять, что работа готова?
  2. Есть ли у задачи один очевидный способ решения?

Два «да» — делайте сразу. Хоть одно «нет» — нужен план.

Сразу делать: ошибка в одном файле, место которой уже показала трассировка; ещё одна проверка входных данных в функции, которую вы можете назвать; правка текста или константы. План здесь только перескажет промпт и добавит лишний круг согласования. Нужнее конкретный промпт (файл, симптом, что значит «исправлено») и проверка, которую Claude запустит сам, — тест или команда, воспроизводящая ошибку.

Plan mode, когда задача меняет устройство системы, а не одно место в ней:

  • меняются границы модулей или сервисов и контракты между ними;
  • переезд на другую библиотеку по всему проекту: мест вызова десятки, и важен порядок шагов;
  • есть несколько путей с разными последствиями для инфраструктуры: новый сервис, брокер сообщений, другая база данных. Какой нужен команде, Claude из кода не узнает — решать вам, и лучше до первой правки.

Пример

Команда бэкенда интернет-магазина разбирает с Claude Code три задачи.

  1. Падает тест расчёта доставки. Трассировка указывает на строку в shipping.py: при пустой корзине вес равен None. Разработчик сразу пишет: «Вот трассировка, исправь и прогони tests/test_shipping.py». Место, причина и проверка известны — решать нечего.
  2. Замена HTTP-клиента. Устаревшая библиотека вызывается в 70 файлах, кое-где со своими настройками повторов и таймаутов. В plan mode Claude находит все места вызова, отмечает нестандартные и предлагает порядок замены с проверкой после каждой группы. Разработчик правит план («модуль платежей пока не трогать») и одобряет его.
  3. SMS-уведомления. Провайдера можно вызывать прямо из обработчика заказа или через очередь с отдельным воркером — второй путь требует брокера сообщений и ещё одного развёртывания. В plan mode Claude изучает инфраструктуру и расписывает оба варианта. Выбирает команда, потом пишется код.

Как это спрашивают

В вопросе описана задача и спрашивается, как её вести. Соблазнительные неверные ходы:

  • «Всегда plan mode — так надёжнее». Для однострочного исправления с понятной трассировкой это лишний круг согласования.
  • «Начнём сразу, план включим, если станет сложно» — для архитектурной задачи. Масштаб виден уже из условия. Без плана Claude выберет подход за команду, и переделывать придётся десятки файлов.
  • Расписать в промпте всё решение и сразу выполнять. Такое устройство никто не сверил с кодом: зависимости и нестандартные места всплывут во время правок. Архитектурной задаче сначала нужны исследование кода и план.
  • Модель покрупнее или effort повыше. Effort управляет тем, сколько Claude думает, а не тем, кто принимает решение: подход Claude всё равно выберет без вас.
  • «Сначала план, код не пиши» в промпте или в CLAUDE.md. Это просьба: Claude обычно её выполняет, но без гарантии. Plan mode блокирует правки средствами самого Claude Code, пока вы не одобрите план (на ноябрь 2026 — кроме терминальной сессии, где доступен bypassPermissions).

Курс vs экзамен

Claude Code 101 называет цикл Explore → Plan → Code → Commit главным рабочим процессом. Экзамен считает plan mode выбором под задачу: для маленького чётко очерченного изменения верный ответ — прямое выполнение. Документация на ноябрь 2026 ближе к экзамену: /plan описан как переход в plan mode «перед большим изменением».

Документация

  • Choose a permission mode: Analyze before you edit with plan mode — Claude исследует и пишет план, исходники не правит; вход через Shift+Tab, /plan или --permission-mode plan.
  • Choose a permission mode: Review and approve a plan — варианты одобрения; одобрение выводит из plan mode, и Claude начинает правки.
  • Choose a permission mode: Common setups — в plan mode Claude Code блокирует правки до одобрения плана.
  • Choose a permission mode: Skip all checks with bypassPermissions mode — в терминальной сессии, где доступен bypassPermissions, блокировки plan mode не действуют; в -p, Agent SDK и чате расширения VS Code они сохраняются.
  • Common workflows: Plan before editing — plan mode для изменений, которые хочется проверить до записи на диск.
  • Common workflows: Fix bugs efficiently — дайте команду, воспроизводящую ошибку, и трассировку стека.
  • Commands: Commands across a typical workflow — /plan переводит в plan mode перед большим изменением.
  • Best practices for Claude Code: Write a specific prompt — файл, симптом и что значит «исправлено»; какой из двух подходов вы предпочитаете, Claude из кода не узнает.
  • Best practices for Claude Code: Give Claude a check to run — проверка с результатом «прошло / не прошло».
  • Best practices for Claude Code: Deterministic and non-deterministic instructions — указания из промпта или CLAUDE.md Claude выполняет по своему усмотрению, без гарантии.
  • Best practices for Claude Code: Change the model and effort — effort управляет тем, сколько Claude думает.
