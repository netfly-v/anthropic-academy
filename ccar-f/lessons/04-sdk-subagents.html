Субагенты в Agent SDK

Домен 1 · подпункт 1.3

  • Subagents · Эффективные субагенты — описание решает, когда субагента запустят и что ему поручат; узкий список инструментов.

Простыми словами

Курсы учат субагентам Claude Code — файлам в .claude/agents/. Экзамен спрашивает про Agent SDK, где субагентов задают в коде.

Определение. Опция agents в query() — словарь «имя → AgentDefinition»:

  • description — когда вызывать: по нему координатор выбирает исполнителя (см. «Координатор и субагенты»);
  • prompt — системный промпт: роль, правила, формат результата;
  • tools — разрешённые инструменты; без этого поля субагент получает все инструменты, доступные субагентам;
  • model — псевдоним, полный ID или inherit.

Запуск. Координатор вызывает инструмент запуска: на экзамене — Task, в текущем SDK — Agent. По логике экзамена без "Task" в allowedTools субагентов не запустить. В вызове два главных поля: subagent_type (какое определение взять) и prompt — конкретная задача, не путать с постоянной ролью из определения.

Контекст. От координатора доходит только строка prompt вызова — разговора субагент не видит. Поэтому в неё пишут всё: цель, входные данные (пути, идентификаторы), что уже решено, ограничения, формат ответа. Каждый вызов начинается с нуля: выводы первого субагента второй получит, только если координатор вставит их в задачу.

Параллельность. Независимые подзадачи координатор раздаёт одним ответом — несколькими вызовами Task, как блоки tool_use в курсе Tool use. Ждать приходится только самого медленного. По одному вызову за ход запускают только зависимые шаги.

Пример

Отдел закупок сети аптек строит на Agent SDK проверку поставщиков перед тендером. Координатор общается с менеджером, субагент supplier-auditor разбирает папку одного поставщика. В первой версии три ошибки.

  1. Задача без контекста. Менеджер согласовал с координатором критерии (поставки в срок — не ниже 95%, период — 2026 год), а субагент получил только «проверь ФармЛогистик». Исправление: в задаче — путь к папке, критерии с порогами, период и формат ответа.
  2. Очередь. Пять поставщиков проверялись по одному. Исправление: правило в системном промпте координатора раздавать независимые проверки одним ответом.
  3. Лишние права. В определении не было tools: субагент унаследовал все инструменты, доступные субагентам, правки одобрялись автоматически — и он «исправил опечатки» в CSV поставщика. Исправление — в определении, а не в промпте.
allowedTools: ["Agent", "Read"],
agents: {
  "supplier-auditor": {
    description: "Audits ONE supplier folder against the procurement criteria it is given.",
    prompt: "You audit a single supplier. Return a table: criterion, value, threshold, verdict, source file.",
    tools: ["Read", "Grep", "Glob"]
  }
}

Первая строка — настройка координатора (на экзамене там "Task"). Ниже — определение: по description субагента выбирают, prompt задаёт формат отчёта, tools оставляет только чтение.

Как это спрашивают

  • Субагент отвечает не по делу, хотя «всё обсуждалось». Модель покрупнее, повторы или фраза «учитывай разговор» не помогут: разговора он не видит. Верно — передать в задаче данные, выводы прошлых шагов и формат ответа.
  • Определения на месте, но субагенты не запускаются. Описания и промпты влияют на выбор, а не на право запуска. По логике экзамена верно — добавить Task в allowedTools.
  • Конвейер медленный. Быстрая модель не уберёт очередь, а один большой агент лишится изоляции контекста. Верно — независимые подзадачи несколькими вызовами Task в одном ответе, а не по одному за ход.
  • Субагент сделал лишнее. Запрет в промпте модель может нарушить. Верно — список tools в AgentDefinition.

Курс vs экзамен

На экзамене отвечайте в его терминах. В SDK на ноябрь 2026 иначе:

  • Имя и allowedTools. С Claude Code 2.1.63 инструмент называется Agent, имя Task принимается как синоним. allowedTools только одобряет инструменты заранее: Agent разрешения не спрашивает и работает без этого списка, а запрещают его через disallowedTools.
  • Контекст. Кроме задачи, субагент получает CLAUDE.md проекта. Форк-субагент (subagent_type: "fork") копирует весь разговор, законченного субагента можно продолжить по agentId, а поле memory даёт ему постоянную папку памяти между запусками.
  • Параллельность. По умолчанию субагент стартует в фоне, поэтому одновременно могут работать и субагенты из разных ходов.

  • Agent SDK reference - TypeScript: Agent — поля вызова (subagent_type, prompt); Task принимается как синоним, в system:init инструмент значится как Task.

  • Configure permissions: Allow and deny rules — allowedTools только одобряет заранее; Agent не спрашивает разрешения; скрыть инструмент — disallowedTools.
