Простыми словами

При долгом исследовании большого репозитория в контексте копятся сотни прочитанных файлов. Документация называет это context rot: с ростом числа токенов модель отвечает менее точно и хуже вспоминает прочитанное. Сжатие освобождает место, но пересказ теряет детали (см. «Длинный контекст»). Симптомы:

  • агент противоречит сам себе: на тот же вопрос о коде отвечает иначе, чем полчаса назад;
  • вместо класса, который он сам открывал утром, говорит «в таких проектах это обычно делает контроллер» — общими словами, а не фактом из этого репозитория.

Правило: всё, что агенту нужно помнить долго, хранится вне контекста — в файле, который он перечитывает. Приёмов три.

Scratchpad-файл с находками. Агент записывает ключевые факты, всегда с путями к файлам: какой класс за что отвечает, где точка входа, какие гипотезы отброшены. На новый вопрос он сначала смотрит в этот файл, а не в память разговора. Готовые механизмы того же рода — инструмент memory в API и поле memory во frontmatter субагента Claude Code.

Сводка между фазами. Обычный субагент не видит разговор главного агента: к нему доходит только текст задания в инструменте Agent (до Claude Code 2.1.63 — Task). Поэтому после разведки координатор сжимает находки в короткую сводку — факты, пути, решения, открытые вопросы — и включает её в задание каждого субагента следующей фазы. Сжимают ход поиска, а не факты (см. «Передача между агентами»).

Манифест для восстановления после сбоя. Каждый агент ведёт файл состояния по заранее заданному пути — что сделано, что найдено, какой шаг следующий — и обновляет его после каждого шага, а не в конце: при падении теряется только текущий шаг. Координатор ведёт манифест — список агентов, их статусы и пути к файлам состояния. При перезапуске он читает манифест, готовое пропускает, а агенту, который продолжает работу, передаёт его файл состояния в стартовом промпте.

Пример

Команда меняет платёжного провайдера в старом сервисе бронирования на несколько тысяч файлов. Сначала разведчики изучают свои области (бронирования, тарифы и штрафы, отчёты), затем планировщики пишут план миграции по каждому из шести модулей.

Через пару часов главный агент на вопрос «какой класс считает штраф за позднюю отмену» отвечает «обычно это сервисный слой», хотя сам нашёл LateCancelFee в booking/pricing/. Потом процесс падает на третьем модуле. Что делает архитектор:

  • разведчики записывают находки с путями в findings/<область>.md, и главный агент отвечает на вопросы по этим файлам;
  • перед второй фазой координатор сводит находки на одну страницу и включает её в задание каждого планировщика;
  • каждый планировщик ведёт state/<модуль>.json, координатор — state/manifest.json. После сбоя координатор читает манифест, пропускает два готовых модуля, а агенту третьего передаёт в промпте его файл состояния.

Как это спрашивают

Типичная ситуация: долгое исследование кода или многофазная работа нескольких агентов; ответы стали путаными или процесс упал посередине. Неверные ходы:

  • модель с большим окном или более сильная модель — точность падает с ростом контекста, а не из-за нехватки места;
  • правило в промпте «помни найденные классы» — деградирует как раз память разговора;
  • положиться только на автоматическое сжатие — пересказ теряет детали, а больше они нигде не записаны;
  • ждать, что субагент «знает» находки главного агента, или отдать ему весь журнал разведки — он видит только задание, а журнал переносит к нему тот же шум; велеть перечитать репозиторий — платить за разведку дважды;
  • после сбоя начать заново или загрузить транскрипты упавших агентов — пропадает готовая работа или в контекст возвращается вся история; документация Agent SDK тоже советует передавать в свежую сессию результаты, а не транскрипты.

Верный ход — состояние в файле по известному пути, который агент перечитывает или получает в промпте: файл не размывается с ростом разговора и переживает и сжатие, и падение процесса.

Документация

  • Context windows — context rot: с ростом контекста падают точность и припоминание.
  • Memory tool — протокол памяти, «assume interruption», шаблон работы в несколько сессий через журнал прогресса.
  • Work with sessions — resume и fork; передать результаты в промпт новой сессии вместо возобновления.
  • Subagents in the SDK — от родителя к субагенту доходит только текст задания в инструменте Agent.
  • Create custom subagents — свежий контекст субагента, поле memory, переименование Task в Agent.
  • Best practices for Claude Code — автоматическое сжатие, субагенту приходится заново собирать контекст, устаревшие советы про размер окна.
