Встроенные инструменты Claude Code

Домен 2 · подпункт 2.5

Что уже есть в курсах

  • API · Агенты и инструменты — набор инструментов Claude Code (Bash, Read, Write, Edit, Glob, Grep) и почему они универсальны.
  • API · Проверка окружения — «прочитай, прежде чем писать»; Edit срабатывает только при точном совпадении текста.
  • API · Текстовый редактор — те же операции с файлами в API: команды view, str_replace, create, insert.
  • Claude Code 101 · Что такое Claude Code — Claude ищет ответы в коде, не загружая его в контекст целиком.

Простыми словами

Экзамен проверяет выбор инструмента под задачу и запасной ход, когда правка не проходит.

  • Grep — поиск по содержимому. Ищет текст внутри файлов по шаблону: где рождается строка ошибки из лога, кто вызывает функцию или импортирует модуль.
  • Glob — поиск по пути и имени. Находит файлы по шаблону имени: **/*.spec.ts — все такие файлы на любой глубине папок. Внутрь файлов не заглядывает.
  • Read и Write — файл целиком. Read читает файл, Write создаёт его или перезаписывает полностью: не дописывает и не сливает.
  • Edit — точечная правка. Заменяет кусок old_string на new_string. Кусок должен совпасть с файлом символ в символ и встречаться в нём ровно один раз.

Если Edit отказал, потому что текст встречается несколько раз, действуют по порядку:

  1. взять кусок длиннее — с соседними строками, которые делают его уникальным;
  2. если менять нужно все вхождения — replace_all: true;
  3. если уникальной «зацепки» нет — Read всего файла, затем Write полной новой версии, собранной из прочитанной. Если в вопросе экзамена зацепки нет, ответ — Read + Write.

Исследовать код — по шагам, а не «прочитать всё». Каждый прочитанный файл остаётся в контексте. Поэтому начинают с зацепки: Grep по тексту ошибки или имени обработчика находит стартовый файл. Его читают через Read и дальше идут по импортам — только по файлам, через которые проходит выполнение.

Модули-обёртки. Обёртка может экспортировать функцию под другим именем или вызывать её внутри своей. Поиск по исходному имени пропустит такие вызовы, поэтому сначала выписывают все имена, которые экспортирует обёртка, и ищут каждое через Grep по всему репозиторию.

Пример

Команда службы доставки работает в Claude Code с репозиторием на TypeScript. В логах дневной смены растёт число ошибок «Courier slot expired»: нужно найти, кто бронирует слот, и поднять таймаут для этой смены. Просьба «прочитай src/ и разберись» исчерпала контекст на сотне файлов. Архитектор ведёт агента от точки входа:

  1. Grep по «Courier slot expired» находит slots/reserve.ts.
  2. Read этого файла показывает, что reserveSlot импортируется из scheduling/index.ts. Следующий Read — туда и только туда.
  3. scheduling/index.ts — обёртка: экспортирует ту же функцию ещё и как bookWindow, а bookWithRetry вызывает её внутри себя. Grep по одному reserveSlot нашёл 4 вызова, по всем трём именам — 19.
  4. Glob src/scheduling/**/*.spec.ts — тесты модуля, которые придётся обновить.
  5. В slots/config.ts три смены (утро, день, ночь) описаны одинаковыми блоками, и timeoutMs: 30000 встречается трижды. Edit отказывает, а различающей зацепки нет: смену определяет только позиция в массиве. Агент делает Read всего файла и Write новой версии с изменённым вторым блоком; git diff подтверждает, что остальное не тронуто.

Как это спрашивают

Типичная ситуация: контекст агента переполнен, найдены не все вызовы или правка не проходит. Соблазнительные неверные ходы:

  • «Сначала прочитать все файлы». Контекст заполнится раньше, чем агент доберётся до сути.
  • Glob для поиска вызовов или Grep для сбора файлов по маске имени. Glob видит только пути, Grep — содержимое.
  • Повторить тот же Edit, взять модель посильнее, написать в промпте «будь точнее». Неуникальный текст от этого уникальным не станет.
  • Write ради одной строки. Write перезаписывает файл целиком; для точечной правки есть Edit.
  • Искать только исходное имя функции. Вызовы через имена из обёртки останутся ненайденными.

Курс vs экзамен

Экзамен считает Grep и Glob постоянными инструментами. На ноябрь 2026 Claude Code на macOS, Linux и WSL по умолчанию их не включает и ищет через Bash (find, grep); вернуть их можно, назвав в --tools или --allowedTools. На Windows они есть сразу. На экзамене роли те же: содержимое — Grep, пути — Glob.
