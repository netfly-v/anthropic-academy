Claude Code в CI: контекст для ревью и тестов

Домен 3 · подпункт 3.6

Что уже есть в курсах

  • Claude Code · Routines и headless — запуск через claude -p, JSON по схеме, --bare, продолжение сессии по ID
  • Claude Code · GitHub Actions и Code Review — управляемый Code Review и свой workflow с claude-code-action
  • API · Claude Code в работе — /init и CLAUDE.md, тесты по схеме «сначала сценарии, потом код»
  • Claude Code 101 · Файл CLAUDE.md — файл читается в начале каждой сессии и коммитится для всей команды

Простыми словами

Запуск в CI — новая сессия без человека рядом: чего нет в контексте, того модель не знает. Архитектор решает, что и откуда попадёт в каждый запуск.

  • Постоянные правила — в CLAUDE.md. Файл лежит в репозитории, и запуск в CI после checkout читает его, как и сессия разработчика (кроме режима --bare, см. «Курс vs экзамен»). Для CI туда пишут критерии ревью (что считать проблемой, что пропускать — например, то, что ловит линтер), стандарты тестов, какие тесты ценны и какие есть фикстуры. Конкретно и проверяемо: не «пиши хорошие тесты», а «проверяй правила отмены брони, данные создавай фабриками из tests/factories.py». Без таких критериев получается объём вместо пользы: тесты на геттеры и на сами моки.
  • Прошлые находки — в промпт повторного ревью. Каждый прогон начинается с чистого листа, и после нового коммита бот повторит то, что уже написал в PR. Передайте ему прошлые комментарии и поставьте задачу сверки: в отчёт — только новые находки и то, что так и не исправили.
  • Существующие тесты — в промпт генерации тестов. По одному diff не видно, что уже проверено. Передайте вместе с diff тестовые файлы модуля и попросите писать тесты только на непокрытое.

Правило выбора: что верно для любого запуска — в CLAUDE.md; что относится к конкретному PR (diff, прошлые находки, тесты модуля) — в промпт этого запуска.

Пример

Команда сервиса бронирования подключила к PR два шага CI на Claude Code: ревью и генерацию тестов. Через неделю: после третьего коммита в PR сорок комментариев бота, большинство — повторы. Новые тесты повторяют сценарии из test_cancellation.py, проверяют очевидное и собирают данные вручную, хотя в проекте есть фабрики.

Архитектор не меняет модель и не дописывает в промпт «будь внимательнее». Он чинит контекст:

  • в CLAUDE.md — разделы «Ревью» (что важно, что пропускать) и «Тесты» (ценные сценарии, чего не писать, какие есть фикстуры);
  • шаг ревью забирает из PR прошлые замечания бота и передаёт их в промпт с задачей сверки;
  • шаг тестов получает вместе с diff тестовые файлы модуля и пишет только недостающие сценарии.

Как это спрашивают

Типичная ситуация: CI-ревью после каждого коммита повторяет свои замечания, или сгенерированные тесты дублируют существующие.

  • Соблазн: правило «не повторяй замечания» или «не дублируй тесты». Без прошлых комментариев и существующих тестов в контексте модели не с чем сравнивать.
  • Соблазн: порог уверенности или модель покрупнее. Порог срежет и новые находки, а крупная модель тоже не знает, что было в прошлом прогоне.
  • Соблазн: ревью один раз на PR. Пропустит проблемы из новых коммитов.
  • Соблазн: продолжить прошлую сессию через --resume. Claude Code ищет сессию на той же машине, а CI-раннер обычно каждый раз новый. Явный список замечаний в свежем запуске надёжнее.
  • Верно: дать недостающие данные, а правила проекта держать в CLAUDE.md, общем для людей и CI, а не копировать в промпт каждого workflow.

Курс vs экзамен

  • CLAUDE.md и --bare. На экзамене CLAUDE.md — способ дать CI-запуску контекст проекта, так и отвечайте. На ноябрь 2026 claude -p и GitHub Action его читают, но для скриптов документация рекомендует --bare, а этот режим CLAUDE.md пропускает: правила тогда передают флагом, например --append-system-prompt-file.
  • Code Review делает это сам. На ноябрь 2026 управляемый сервис читает CLAUDE.md и REVIEW.md, а повторное ревью само закрывает свои замечания, которые считает исправленными. В своём пайплайне прошлые находки передаёте вы.

  • Best practices for Claude Code — что класть в CLAUDE.md (команды тестов, соглашения, неочевидное); почему ревьюер без ограничений находит лишнее
