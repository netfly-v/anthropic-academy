Координатор и субагенты

Домен 1 · подпункты 1.2, 1.3

Что уже есть в курсах

  • Platform 101 · Что такое Managed Agents — координатор раздаёт алерт трём специалистам и сводит их выводы; отдельный грейдер возвращает работу на доработку.
  • API · Маршрутизация — запрос уходит в один подходящий конвейер, а не во все.
  • API · Агенты и рабочие процессы — цикл evaluator-optimizer: оценщик возвращает результат с замечаниями, пока не примет.
  • Subagents · Эффективные субагенты — главный агент выбирает субагента по описанию; формат результата подсказывает, когда остановиться.

Простыми словами

Схема «звезда» (hub-and-spoke): в центре координатор, вокруг субагенты. Субагенты не общаются друг с другом: каждый получает задание от координатора и ему же возвращает результат. Координатор решает, кого звать, делит вопрос, раздаёт части и сводит ответы в итог.

Зачем вести всё через центр:

  • Видимость. Все задания и отчёты видны в одном месте; в Managed Agents это главный поток сессии.
  • Единая обработка ошибок. Если субагент прервался, например из-за ошибки API, об этом узнаёт координатор и решает: повторить, взять другой источник или отметить пробел.
  • Контроль над информацией. Субагент знает о задаче только то, что координатор вписал в задание (подробнее — «Субагенты в Agent SDK»).

Четыре решения координатора:

  • Кого звать — по сложности запроса. Один факт, сравнение или анализ последствий требуют разного состава и числа субагентов, а не всего конвейера на каждый запрос. Документация советует: задачу на несколько вызовов инструментов делать самому, а если хватает одного субагента — звать одного.
  • Как делить — без пересечений. Сначала перечислить стороны вопроса, которые должен охватить итог, и только потом делить работу — по темам или по источникам данных. Участки не перекрываются и вместе закрывают весь список; в задании сказано, чем субагент не занимается. Так слишком узкое деление, частая причина однобокого отчёта, видно ещё до запуска.
  • Как закрывать пробелы. Черновик итога координатор сверяет со списком сторон: по каждой непокрытой даёт точечное задание тому субагенту, чей это участок, и пересобирает итог — пока список не закрыт или не исчерпан лимит кругов. Что осталось открытым, отчёт называет прямо.
  • Что писать в задании — цель, а не сценарий. Цель, границы участка, критерии качества, формат результата. Пошаговая процедура ломается на первом неожиданном источнике.

Пример

Исследовательская система логистической компании: координатор, два поисковых субагента, один по внутренним данным и один для синтеза. На вопрос «Что изменится для наших автоперевозок, если ЕС введёт углеродный сбор для грузовиков?» приходит отчёт только о ставках и сроках сбора, с повторами и без договоров с клиентами, конкуренции с железной дорогой и обновления парка. А справка «с какого числа действует сбор» готовится десять минут.

Причина в координаторе: все подзадачи он строит вокруг самого сбора, обоим поисковым субагентам даёт одно задание и на любой вопрос зовёт всю четвёрку. Что меняет архитектор:

  1. На вопрос о факте — один поисковый субагент; полный состав — для вопросов о последствиях.
  2. Участки — по типам источников: законы, отраслевая аналитика, внутренние договоры и данные о рейсах.
  3. Список сторон — затраты, договоры, конкуренты, сроки, парк — составляется до раздачи, по нему проверяется черновик синтеза. Пробел закрывает точечное задание («какие договоры позволяют переложить сбор на клиента») и новый синтез — не больше двух дополнительных кругов.
  4. Вместо «открой пять ссылок и выпиши цифры» задание называет цель, участок, критерии (каждый факт с источником, прогноз отдельно от факта) и формат ответа.

Как это спрашивают

Типичная ситуация: отчёт однобокий или с повторами, простая справка долгая и дорогая, сбой одного источника остаётся незамеченным. Соблазнительные неверные ходы:

  • Чинить исполнителей: модель побольше, другой поисковик, больше повторов. Сильный исполнитель лишь тщательнее раскопает тот же узкий участок.
  • Всегда запускать весь конвейер «для надёжности». Время и цена растут, а качество ответа на простой вопрос — нет.
  • Прямой обмен между субагентами «ради скорости» — даже там, где продукт его допускает (в Claude Code и Agent SDK — инструмент SendMessage). Пропадают общий журнал, единая обработка ошибок и контроль над тем, что видит каждый агент.
  • Поручить субагенту синтеза заполнить пробелы. Он заполнит их по памяти, без источников.
  • Пошаговый сценарий в задании. Субагент перестаёт приспосабливаться к тому, что нашёл.

Верный ход — в координаторе: выбор по сложности, деление без пересечений, точечное закрытие пробелов, связь только через центр.

Документация

  • Multiagent orchestration — что делегировать (параллельные независимые подзадачи, специализация), делегирование субагентам на один уровень, пример указаний для workflow run: как делить работу, перепроверять и называть непокрытое.
  • Session threads — главный поток: начало и конец работы субагентов, задания и отчёты; поток каждого субагента — отдельно.
  • Subagents in the SDK — выбор субагента по description, субагенту (кроме форка) передаётся только промпт из вызова инструмента Agent, лимиты глубины и числа субагентов.
  • Create custom subagents — вложенные субагенты до трёх уровней, SendMessage, сбой субагента на ошибке API возвращается Claude; Task переименован в Agent в версии 2.1.63.
  • Prompting best practices: Subagent orchestration — когда субагенты оправданы, а когда работать напрямую.
  • Prompting best practices: Research and information gathering — явные критерии успеха и проверка по нескольким источникам.
  • Prompting best practices: Leverage thinking and interleaved thinking capabilities — общие указания вместо расписанного пошагового плана (о рассуждениях модели).
  • Prompting Claude Opus 5: Controlling subagent spawning — делегировать только крупные независимые задачи, звать одного субагента, если его хватает; жёсткие лимиты.
  • How we built our multi-agent research system — фон (Anthropic Engineering): ведущий агент подбирает число субагентов под сложность запроса; расплывчатые задания ведут к дублированию и пробелам.
