Routines и headless

Чему научитесь

Видео 3:08 и текст урока

К концу урока вы сможете:

  • объяснить, что объединяет routine и по каким триггерам она запускается;
  • создать routine на сайте или командой /schedule, помня о трёх её ограничениях;
  • запускать Claude Code из скриптов через claude -p, получать JSON по схеме и продолжать сессию по её ID;
  • выбирать между routine, headless-режимом, --bare и Agent SDK.

Видео и текст урока.

Когда вы уже доверяете Claude какую-то задачу, следующий шаг — перестать делать её вручную. Если это один и тот же промпт, который запускается по повторяющемуся триггеру, незачем каждый раз сидеть и запускать его самому. В этом уроке — два способа снять с себя такую работу: routines, где вам ничего не нужно строить, и headless-режим, где вы полностью управляете запуском из своих скриптов.

Представьте себе шкалу. На одном её конце — routines, которые работают на управляемой инфраструктуре Anthropic. На другом — headless-режим и Agent SDK: они запускают Claude Code из вашего собственного кода. Начнём с того конца, где строить приходится меньше всего.

Routines: сохранённый промпт, который работает в облаке

Routine — самый прямой способ автоматизировать задачу. Не нужно ни скрипта, ни сервера. Она объединяет три вещи: промпт, репозиторий, с которым она работает, и нужные ей коннекторы. И запускает этот набор в облаке каждый раз, когда срабатывает триггер.

Главное здесь то, что инфраструктура принадлежит Anthropic. Не нужно оставлять свою машину включённой на ночь, и нет файла workflow, который пришлось бы поддерживать. Вы один раз описываете работу, и она просто выполняется.

Routine может запускаться по триггерам нескольких видов:

  • расписание cron, например каждое утро в 9:00;
  • HTTP POST на её API-эндпоинт — так её может запустить ваш собственный код;
  • событие GitHub, например появление нового pull request.

Подходит всё, что сводится к одному и тому же промпту по повторяющемуся триггеру. Утренний аудит зависимостей. Сортировщик PR, который срабатывает, когда приходит новый pull request. Ежедневный разбор тикетов Sentry, чтобы понять, что срочнее всего.

Вот как стоит представлять routine: она связывает промпт, репозиторий, коннекторы и расписание.

Два способа её создать

Routine можно создать на сайте claude.ai/code/routines. Вы даёте ей имя, пишете инструкции — что Claude должен делать в каждой сессии, — выбираете репозиторий и триггер.

А можно создать её прямо из Claude Code, не выходя из терминала. Запустите команду /schedule и опишите обычными словами, что вам нужно, например:

/schedule daily dependency audit at 9am

Идея одна, входа два. Выбирайте тот, что удобнее в вашей работе.

Три вещи, которые нужно знать, прежде чем полагаться на routines

Прежде чем доверять routines что-то важное, помните о трёх ограничениях.

  • Routines пока в статусе research preview. Поведение и лимиты будут меняться, так что не удивляйтесь переменам.
  • Повторяющееся расписание срабатывает не чаще раза в час. Если нужно чаще, routines — не тот инструмент.
  • Каждый запуск начинается со свежего клона ветки по умолчанию и может делать push только в ветки с префиксом claude/, если вы не ослабите это ограничение для конкретного репозитория. Именно эта защита не даёт автономному запуску переписать main.

Пояснение

  • Новое название. На ноябрь 2026 документация Claude Code называет routines «scheduled tasks» (cloud scheduled task, «formerly a routine»). Функция та же, старое имя осталось в адресе claude.ai/code/routines и местами в интерфейсе.
  • Ветка claude/ — умолчание, а не запрет. По текущей документации push по умолчанию идёт в ветку с префиксом claude/, но промпт может направить его в другую ветку. Отдельной настройки «ослабить для репозитория», о которой говорит урок, в документации нет: какие ветки закрыты для записи, задают branch protection rules или rulesets на GitHub. Так что main защищает правило на GitHub, а не сама routine.

Headless-режим: когда нужно ваше окружение

Routines хороши, когда работу можно сделать в облаке. Но иногда задаче нужно ваше окружение или своя логика вокруг запуска. Тогда спускайтесь к headless-режиму.

Основа headless-режима — флаг -p (сокращение от --print). Он запускает Claude Code как разовую команду без интерактивного интерфейса. Команда читает стандартный ввод и пишет в стандартный вывод, поэтому её можно встраивать в конвейер, как любой другой инструмент оболочки:

claude -p "summarize the changes in this diff"

Одно важное замечание: -p пропускает автообнаружение hooks, skills, плагинов, MCP-серверов и файла CLAUDE.md. Вы получаете Claude плюс инструменты, которые разрешили явно, и ничего из того, что случайно подгрузило бы локальное окружение. Зато запуск так проходит гораздо быстрее.

Пояснение

  • В тексте урока здесь ошибка. В видео эта фраза сказана про --bare, и документация Claude Code (на ноябрь 2026) это подтверждает: автообнаружение hooks, skills, плагинов, MCP-серверов и CLAUDE.md пропускает именно --bare. Обычный claude -p всё это находит и загружает, как интерактивная сессия, а в чужом репозитории запускает hooks и MCP-серверы проекта без диалога доверия.
  • «Детерминированный» — про окружение, а не про ответы. Ниже урок называет --bare детерминированным режимом. Документация называет его bare mode, минимальным режимом: одинаковой на любой машине становится конфигурация, потому что чужие hooks и MCP-серверы он не читает. Ответы модели от запуска к запуску всё равно могут различаться.

Получаем структурированный вывод

Раз headless-режим встраивается в конвейер, как любой инструмент оболочки, часто вам нужны структурированные данные, а не обычный текст. Можно передать JSON-схему вместе с форматом вывода JSON, и Claude ограничит свой ответ так, чтобы он соответствовал вашей схеме.

Объект, который соответствует схеме, попадает в поле structured_output JSON-ответа. Его можно извлечь командой jq и передать в базу данных или в другой скрипт:

claude -p "Extract the exported function names from src/core/style.js" \
  --output-format json \
  --json-schema '{"type":"object","properties":{"functions":{"type":"array","items":{"type":"string"}}},"required":["functions"]}' \
  | jq '.structured_output.functions'

Так вы получаете чистый массив, который можно отдать следующему шагу.

Многошаговая автоматизация через сессии

Если работа идёт в несколько шагов, не нужно втискивать всё в одну команду. Сохраните ID сессии из JSON-вывода и продолжите её позже:

claude --resume "$(jq -r .session_id /tmp/plan.json)"

Один скрипт запускает работу. Другой позже продолжает её с полным контекстом. Это удобно, когда первый проход составляет план, а второй его выполняет.

Пояснение

  • В скрипте добавьте -p. Команда из урока без -p откроет восстановленную сессию в интерактивном режиме. Чтобы второй шаг тоже выполнялся без участия человека, передайте ему промпт, как в документации: claude -p "Continue that review" --resume "$session_id".
  • Откуда /tmp/plan.json. Подразумевается, что первый шаг сохранил в этот файл свой JSON-вывод, например так (команды в уроке нет): claude -p "Plan the migration" --output-format json > /tmp/plan.json.

Детерминированные запуски для CI

Когда CI должен получать один и тот же результат при каждом запуске, для этого есть специальный режим.

Флаг --bare включает детерминированный режим. Это правильный выбор, когда вы запускаете Claude Code внутри пайплайна и хотите повторяемый, предсказуемый результат, а не такой, который меняется от запуска к запуску.

Agent SDK: Claude Code внутри вашего приложения

Последняя точка на шкале — Agent SDK. Это библиотека, которая встраивает Claude Code в ваши собственные приложения на TypeScript или Python.

В обоих языках есть функция query и те же примитивы, что и в CLI. Вы передаёте промпт и параметры, например:

  • allowedTools — чтобы управлять тем, что Claude может делать;
  • системный промпт;
  • режим разрешений.

Потом перебираете сообщения, которые Claude присылает потоком, и обрабатываете их так, как нужно вашему приложению. Это тот же движок, что и в CLI, только вызывается он изнутри вашего продукта.

Что выбрать?

Короткая шпаргалка:

  • Routines — вариант по умолчанию для повторяющейся работы. Они работают на инфраструктуре Anthropic, и вам ничего не нужно хостить.
  • Headless-режим с -p — когда задаче нужен ваш пайплайн и вы хотите пропускать данные через скрипт.
  • --bare — когда CI должен получать один и тот же результат при каждом запуске.
  • Agent SDK — когда работа должна жить внутри вашего собственного продукта.

Начинайте с routines. Спускайтесь по шкале, только когда задаче действительно нужен дополнительный контроль.
