Плагины

Чему научитесь

Видео 3:09 и текст урока

К концу урока вы сможете:

  • объяснить, что такое плагин и что он объединяет в одну установку;
  • установить плагин и подключить маркетплейс для команды;
  • проверить плагин до установки: его hooks, агентов, MCP-серверы и ключ agent;
  • упаковать свою папку .claude в плагин с манифестом .claude-plugin/plugin.json.

Видео и текст урока.

Настройка, которой вы доверяете, стоит гораздо больше, когда ею пользуется вся команда. Сложность в том, как её перенести. Вы собрали отличную папку .claude со skills, субагентами и hooks — а дальше что? Все копируют файлы с машины на машину и надеются, что копии не разойдутся. Плагины решают эту проблему. Плагин — это способ, которым Claude Code упаковывает настройку и передаёт её от одного человека к другому.

У темы две стороны, и мы разберём обе. Первая — пользоваться плагинами, которые публикуют другие. Вторая — упаковать собственный, когда вы сделали что-то, чем стоит поделиться.

Что такое плагин

Плагин — это одна устанавливаемая единица. В него входит всё, чем иначе пришлось бы делиться вручную: skills, субагенты, hooks и конфигурации MCP-серверов, а сверх того — длинный хвост прочего, например серверы LSP (language server protocol), фоновые мониторы, темы и часть settings.json. Одна версия, одна установка.

От того, где лежит плагин, зависит, как его устанавливать. Внутри сессии плагин можно поставить прямо по имени:

/plugin install org-name@plugin-name

Вот как это выглядит: Claude Code устанавливает плагин и предлагает выполнить /reload-plugins, чтобы применить изменение.

Пояснение

  • Порядок в команде. По документации Claude Code (на ноябрь 2026) команда выглядит так: /plugin install <плагин>@<маркетплейс> — сначала имя плагина, после @ имя маркетплейса, например /plugin install commit-commands@claude-plugins-official. В примере урока org-name@plugin-name части названы в обратном порядке. Официальный маркетплейс claude-plugins-official Claude Code добавляет сам, плагин из любого другого ставят после того, как его маркетплейс добавлен.
  • Установка идёт через панель. В сессии команда не ставит плагин сразу, а открывает панель /plugin на карточке плагина. Там вы смотрите, что он добавит, и выбираете область установки: user, project или local.

Как добавить маркетплейс для команды

Для команды лучше один раз добавить закрытый маркетплейс. Маркетплейс — это общий источник, из которого берутся плагины:

/plugin marketplace add your-org/claude-plugins

Назвать его можно как угодно. Когда он добавлен, каждая следующая установка идёт через него. Поиск плагинов, отслеживание версий и обновления собраны в одном месте, а не разбросаны по ноутбукам всей команды.

Что доступно, можно посмотреть на вкладке Discover. Там перечислены плагины из ваших маркетплейсов, их можно искать и выбирать.

Прочитайте до установки

Это самое важное. Плагин выполняет код на вашей машине с вашими правами. Его hooks срабатывают на каждый подходящий вызов инструмента. Поэтому если вы ставите плагин ради его skills, вы получаете и его hooks PreToolUse и Stop — читали вы их или нет.

Подумайте, что это значит. Плагин из сообщества может содержать hook Stop, который каждый раз обращается к какому-то сетевому адресу, и ничто в вашей конфигурации об этом не предупредит. Это не причина отказываться от плагинов. Это причина сначала посмотреть.

Перед установкой изучите карточку плагина. Claude Code показывает, что будет установлено, и оценивает, сколько контекста займёт плагин, а рядом — прямое предупреждение: Anthropic не контролирует, что находится внутри сторонних плагинов.

О том, откуда берутся плагины, стоит знать две вещи:

  • Плагин, поданный через форму в самом приложении, после автоматической проверки Anthropic попадает в маркетплейс сообщества.
  • Официальный маркетплейс курируется отдельно, своим порядком.

Но «проверен» не значит «надёжен». Автоматическая проверка ловит кое-что, но не всё. Так что правило остаётся в силе: ставьте плагины и добавляйте маркетплейсы только из источников, которым действительно доверяете, и проверяйте, что плагин на самом деле делает, прежде чем его включить.

Пояснение

  • Чего карточка не показывает. Она перечисляет компоненты плагина, но не показывает, что запускает hook: это видно только в исходниках (hooks/hooks.json, .mcp.json). Оценку контекста на ноябрь 2026 показывают только для плагинов официального маркетплейса Anthropic, и не в списке Discover.
  • Откуда плагины берутся сейчас. Порядок подачи со времени записи курса изменился. На ноябрь 2026 автор подаёт плагин в каталог Anthropic на claude.ai через портал claude.ai/directory/manage; прежняя форма подачи в Claude Console больше не поддерживается. Каждая версия проходит автоматическую проверку, а новую публикацию дополнительно проверяет человек. Маркетплейс сообщества claude-community Claude Code сам не добавляет. Сторонние маркетплейсы, в том числе ваш командный, Anthropic не проверяет вовсе.

Компоненты работают рядом с вашими

Плагин не перезаписывает вашу конфигурацию. Его компоненты работают рядом с вашими. В основном это хорошо, но есть последствия, которые стоит понимать.

Hooks складываются. Hook PreToolUse плагина и ваш собственный hook PreToolUse срабатывают оба на каждый вызов инструмента. Ни один не заменяет другой. Именно поэтому карточку читают заранее.

Skills, агенты и команды получают пространство имён по имени плагина, поэтому никогда не конфликтуют с вашими. В плагин можно положить и файл settings.json, но очень ограниченный. Claude Code учитывает из него всего два ключа: agent и ключ строки состояния субагентов.

На ключе agent стоит остановиться. Если он задан, один из субагентов плагина становится главным потоком сессии — вместе со своим системным промптом, ограничениями на инструменты и моделью. Иначе говоря, включение плагина может изменить поведение Claude Code по умолчанию. Это одна из главных причин посмотреть на плагин ещё до того, как вы его включите.

Когда плагин установлен, в панели плагинов можно увидеть всё, что он добавил, управлять им и удалить его.

Как упаковать свой плагин

Теперь вторая сторона. Когда у вас есть работающая папка .claude, не заставляйте команду копировать её между машинами. Упакуйте её.

Хорошая новость: ничего не нужно перестраивать. Плагин устроен так же, как привычная вам папка .claude:

  • по папке на каждый skill;
  • по Markdown-файлу на каждого субагента в папке agents;
  • hooks/hooks.json и .mcp.json — в корне плагина.

Основную работу делает структура каталогов: Claude Code находит компоненты по соглашению.

Манифест

К этому можно добавить необязательный манифест. Он лежит в .claude-plugin/plugin.json и хранит имя, версию, описание и автора:

{
  "name": "svg-splitter-review",
  "version": "0.1.0",
  "description": "Reviews the SVG Splitter repo",
  "author": {
    "name": "Lewis Menelaws"
  }
}

Манифест необязателен. Без него Claude Code всё равно найдёт ваши компоненты по структуре каталогов. Но пару деталей знать стоит:

  • Имя — единственное обязательное поле. Оно задаёт пространство имён для ваших skills в виде company-name:skill-name, поэтому они не конфликтуют с чужими.
  • Версионируйте плагин, как любую другую зависимость. Именно на этом держатся обновления и отслеживание версий во всей команде.

Пояснение

  • Что стоит перед двоеточием. Префикс — это поле name плагина, а не название компании: skills из примера вызываются как /svg-splitter-review:<skill>. Без манифеста имя берётся из записи в маркетплейсе.
  • Где лежат файлы. Компоненты лежат в корне плагина, без префикса .claude/; hooks из settings.json переезжают в hooks/hooks.json в той же форме. Внутри .claude-plugin/ лежит только манифест.
  • Как работает версия. Пока version не меняется, пользователи остаются на этой версии, даже если вы пушите новые коммиты. Поэтому либо поднимайте её в каждом релизе, либо, если плагин раздаётся через git, не указывайте её вовсе — тогда версией служит SHA коммита (на ноябрь 2026).

Главное

Почти всё здесь сводится к двум простым правилам:

  • Пользуетесь плагинами — читайте до установки. Плагин выполняет код с вашими правами, поэтому сначала посмотрите на его hooks, агентов и MCP-серверы.
  • Делаете свой — упакуйте папку .claude, как только она заработала. Один манифест, одна установка.

В этом весь смысл. Одна устанавливаемая единица — и настройка, которой вы доверяете, доходит до всей команды.
