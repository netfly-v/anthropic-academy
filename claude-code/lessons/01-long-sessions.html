Долгие сессии

Чему научитесь

Видео 3:45 и текст урока

К концу урока вы сможете:

  • очерчивать рамки работы в plan mode до того, как Claude начнёт менять код;
  • направлять сжатие контекста инструкциями после /compact и откатываться через меню rewind;
  • задавать условие готовности через /goal и повторять промпт через /loop;
  • разводить параллельные сессии по отдельным worktree.

Видео и текст урока.

Попросить Claude быстро выполнить небольшую задачу просто: вы просите, он делает, вы проверяете результат. С долгими задачами всё иначе. Рефакторинг на десяток файлов или разработка новой функциональности могут занять часы. И чем чаще вам приходится поправлять Claude по ходу, тем дольше всё тянется.

Хорошая новость: у вас много средств, чтобы помочь Claude в таких долгих сессиях. Всё сводится к двум привычкам: очертить рамки работы до того, как Claude начнёт, и направлять его, пока он работает. Разберём обе.

Сначала очертите рамки работы в plan mode

Прежде чем Claude напишет хоть одну строчку, пусть он составит план. В plan mode Claude исследует задачу в режиме только для чтения: читает код, выясняет, что нужно изменить, и отдаёт вам план на проверку.

Когда план готов, прочитайте его по-настоящему. Не пробегайте глазами. Чем подробнее план, тем меньше сюрпризов будет, когда Claude начнёт его выполнять. Если что-то не так или чего-то не хватает, просто попросите Claude добавить это туда, куда нужно. Доработать план гораздо быстрее, чем пустить Claude в работу в надежде на лучшее, а потом разгребать последствия.

Пояснение

Plan mode включают клавишами Shift+Tab (нажимайте, пока в строке состояния не появится ⏸ plan mode on) или командой /plan в начале промпта. «Только чтение» относится к вашему коду: по документации Claude Code (на ноябрь 2026), Claude может запускать команды оболочки, чтобы разобраться, но исходники не правит, пока вы не одобрите план.

Направляйте Claude, пока он работает

Когда Claude уже работает, есть несколько способов удерживать его на верном курсе. Первый — сжатие контекста.

Сжатие (compact)

Compact составляет краткое содержание разговора, делает его новым контекстом и удаляет старые сообщения. Так освобождается окно контекста, и Claude может продолжать. Риск в том, что при пересказе потеряется что-то важное и Claude собьётся с курса.

Поэтому не запускайте /compact без аргументов. Допишите после команды указания, как Claude составить краткое содержание. Например, если отладку вы закончили давно, а сейчас вас интересуют только изменения API, так и скажите:

/compact Focus on the --version flag implementation

Всё, что вы напишете после команды, определит, что останется в кратком содержании. Это ваш руль для контекста.

Откат (rewind)

Когда Claude свернул не туда, не нужно выводить его обратно промптами. Rewind возвращает вас к последней контрольной точке (checkpoint). Каждый ваш промпт создаёт контрольную точку, к которой можно вернуться. Чтобы открыть меню, дважды нажмите Esc при пустой строке ввода.

В меню rewind есть несколько вариантов:

  • Restore code and conversation — откатить и код, и разговор.
  • Restore conversation — откатить только переписку.
  • Restore code — откатить только файлы.
  • Summarize from here — кратко пересказать всё, что было после контрольной точки. Удобно, если у вас был побочный разговор и вы просто хотите освободить место.
  • Summarize up to here — кратко пересказать всё, что было до контрольной точки. Удобно, когда была долгая подготовительная фаза и её хочется сжать, а части с реализацией оставить нетронутыми.

Пояснение

  • Не только последняя точка. По документации (на ноябрь 2026), в меню rewind (его открывает и команда /rewind) список всех ваших промптов за сессию: вернуться можно к любому, а не только к последнему, как сказано в уроке.
  • Что не откатывается. Контрольные точки следят за правками, которые Claude делает своими инструментами редактирования. Файл, который меняли только команды оболочки (скрипт, mv, rm), не отслеживается; правки субагентов и ваши ручные изменения вне Claude Code обычно тоже. Это быстрый откат внутри сессии, а не замена git.

Дайте Claude больше самостоятельности

Всё, что было выше, предполагает, что вы у руля: следите и поправляете. Если хотите, чтобы Claude работал самостоятельнее, есть goal и loop.

Цель (goal)

Goal задаёт условие завершения. Вы описываете, как выглядит «готово», и Claude продолжает работать ход за ходом, пока быстрый оценщик не подтвердит, что условия выполнены. Он не остановится, как только впервые решит, что закончил.

Например:

/goal all tests in src/billing pass, and the type checker reports zero errors

Чтобы отменить цель, выполните /goal clear. Важное ограничение: оценщик читает только транскрипт. Поэтому условие должно проверяться по тому, что Claude действительно выводит, — например, по результатам прогона тестов.

Цикл (loop)

Loop запускает промпт с интервалом между ходами — фиксированным или подобранным самим Claude. Используйте его, чтобы опрашивать что-то внешнее, например прогон CI или деплой, и действовать, когда состояние изменится.

Чтобы остановить цикл, просто нажмите Esc.

Параллельная работа в worktree

Метафора с рулём до сих пор предполагала один руль в одной машине. Но когда над одной кодовой базой работают несколько агентов, два руля в одной машине вам не нужны. Это опасно. Когда две сессии Claude борются за одни и те же файлы, возникают конфликты.

Здесь и пригодятся worktree. Сессии больше не мешают друг другу: каждая получает собственное независимое дерево файлов.

Раз у каждого агента своё дерево, они не могут затереть изменения друг друга. Когда сессия завершается, чистый worktree удаляется автоматически.

Есть один полезный файл, о котором стоит знать. Файл .worktreeinclude в корне репозитория перечисляет игнорируемые git файлы, которые нужно копировать в каждый worktree. Это удобно, например, для файла с переменными окружения или локального конфига: они нужны в каждом worktree, но коммитить их в систему контроля версий не хочется.

Пояснение

  • Esc останавливает не всякий цикл. По документации (на ноябрь 2026), Esc останавливает цикл с интервалом от Claude, пока тот ждёт следующего прохода. Цикл с фиксированным интервалом вроде /loop 5m клавишами Esc и Ctrl+C не остановить: попросите Claude его отменить.
  • Как запустить worktree и когда он удаляется. claude --worktree feature-auth запускает сессию в новом worktree. Без вопросов при выходе удаляется только чистый worktree безымянной сессии; для именованной сессии и для worktree с изменениями или новыми коммитами Claude Code спрашивает, оставить его или удалить.

Собираем всё вместе

Работа с долгими сессиями Claude Code сводится к нескольким привычкам:

  1. Сначала очертите рамки работы, потом направляйте.
  2. Направляйте сжатие, чтобы в кратком содержании осталось важное.
  3. Откатывайтесь через меню rewind, когда Claude сбивается с курса.
  4. Ставьте цель, когда «готово» вы можете описать лучше, чем шаги к нему.
  5. Параллельную работу ведите в worktree.

Делайте так — и сможете доверять долгому запуску, не присматривая за каждым его шагом.
